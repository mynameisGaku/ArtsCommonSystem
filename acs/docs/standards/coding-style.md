# ACS コーディング規約

この規約は、新規作成または変更する ACS の C++ ソース、ヘッダー、テスト、ツールに適用します。既存コードには規約と異なる箇所が残る場合がありますが、変更する範囲では対象モジュールの契約を保ちながら規約へ合わせます。既存モジュールの所有権、エラー型、命名、ビルド機構を優先し、同じ責務を持つ別の基盤を追加しません。

## 型名

| 接頭辞 | 用途 | 例 |
|---|---|---|
| `A` | ACSが所有し、多態的に扱うオブジェクト | `ANode`, `AComponent` |
| `C` | 状態と処理を持つ機能クラス | `CAcpakReader` |
| `F` | 値、結果、ハンドル、サービス | `FVec3`, `FDeviceConfig` |
| `I` | 実装を差し替える純粋インターフェース | `IRhiDevice` |
| `T` | クラステンプレート | `TArray`, `TUniquePtr` |
| `E` | `enum` / `enum class` | `ELogSeverity` |

接頭辞は文法ではなく、責務、所有権、寿命で決めます。既存の `FScene` は公開APIとの互換性のために名称を維持している例外であり、新規の所有される多態オブジェクトの命名例にはしません。コールバック、デリゲート、関数ポインターの別名には特定の接頭辞を強制しません。

## 識別子

| 対象 | 形式 |
|---|---|
| 型、関数、メソッド | `PascalCase` |
| 引数、ローカル変数 | `snake_case` |
| `private` / `protected`のフィールド | `m_PascalCase` または対象モジュールで統一された `m_` 形式 |
| コンパイル時定数 | `kPascalCase` |
| 列挙値 | `PascalCase` |
| マクロ | `ACS_UPPER_CASE` |

新しい内部名に先頭 `_` を使いません。公開APIの既存名を移行する場合は、利用側を同時に更新できないときだけ一時的な `using` 別名を置きます。

## ファイル

- 公開型は原則として1主要型1ヘッダーにします。
- 非`template`実装は同名 `.cpp` に置きます。
- `template`実装は同名ヘッダーまたは `.inl` に置きます。
- ヘッダーの先頭は SPDX とインクルードガードだけにします。
- インクルードは意味上の依存順を維持し、機械的に並べ替えません。
- モジュール、プラグイン、機能ディレクトリを責務境界にします。

## コメント

型と関数の宣言直前には、役割、入力、戻り値、失敗条件が分かる日本語コメントを書きます。フィールド、グローバル変数、ローカル変数、定数、列挙値にも、その場所での役割が分かる短い日本語コメントを置きます。

専門用語が必要な場合は、その直後に ACS 内での意味を短く補足します。途中の行コメントで式を分断せず、対象式の直前へ置きます。

## 所有権と寿命

- 単独所有には `TUniquePtr` を使います。
- ACSオブジェクトの強参照には `TObjectPtr`、非所有参照には `TWeakObjectPtr` を使います。
- 生ポインターは非所有、ABI、OS API など境界が明確な場合に限定します。
- `friend` で責務境界を広げず、明示的なアダプターまたは公開操作を用意します。
- サブシステムは複数利用者、明確な所有者と寿命、更新または終了処理を持つ場合だけ作ります。

## エラー

失敗し得る処理は `TResult<T>`、`FErrorCode`、機能固有の結果型のいずれかで失敗を明示します。`bool` を使う場合は失敗理由が不要な局所判定に限定します。失敗時に出力引数や所有権を半端に変更しません。

## 書式

`.clang-format` を使用し、次を維持します。

- インデントは空白4文字です。
- ポインターと参照は型側へ寄せます。
- 関数本体の開始波括弧は次の行に置きます。
- 関数の宣言、定義、呼び出し、条件式、キャスト、直接初期化、マクロ呼び出しでは、丸括弧または初期化子の内部を長さにかかわらず1行にします。
- 引数または初期化子の途中にある行コメントは、対象となる式の直前へ独立した行として移します。
- `lambda` の本体は複数行のままで構いません。安全に1行へまとめられない周辺式は、名前付きのコールバックへ分けます。
- 行幅による自動折り返しを行いません。
- LF を使用します。

対象モジュールに既存の波括弧配置がある場合は、そのファイルの形式を維持します。

## 検証

```pwsh
python .\scripts\normalize_cpp_argument_lists.py --self-test
python .\scripts\normalize_cpp_argument_lists.py --check
python .\scripts\audit_cpp_conventions.py --root .
python .\scripts\audit_cpp_type_roles.py --root .
python .\scripts\audit_cpp_comment_coverage.py --root .
cmake --build .\Intermediate\vs --config Debug
ctest --test-dir .\Intermediate\vs -C Debug --output-on-failure
```

既定の走査範囲は `src`、`tests`、`tools`、`samples` です。変更範囲だけを確認するときは `--scope`、同時に変更されている範囲を除外するときは `--exclude` を繰り返して指定できます。

```pwsh
python .\scripts\normalize_cpp_argument_lists.py --check --scope src --exclude src\ui
```

安全に機械変換できる範囲は `--write` で修正できます。プリプロセッサ指令または改行を含む生文字列など、自動変換できない構文は変更せずに位置を報告します。通常のCTestでは `ACS.CppArgumentLayoutAuditSelfTest` が監査器の自己テストを実行します。

公開API、ソース配置、機能を変更した場合は、関連する ACS 文書とリファレンス生成元を同時に更新します。
