# 単純デリゲートとタイマーサブシステム

`FSimpleDelegate`は引数なしの関数またはメンバー関数を、任意データと一緒に保持します。
メモリ確保を行わず、未設定時は`ExecuteIfBound`が`false`を返します。

引数や戻り値が必要な場合は`TDelegate<戻り値(引数...)>`を使います。複数の処理を
登録する場合は`TMulticastDelegate<void(引数...)>`を使います。メンバー関数の登録時は
型が一致するか検査され、複数登録した処理の保存と世代管理には既存の`TEvent`を使います。
引数なしの複数登録には`FSimpleMulticastDelegate`を使えます。
複数登録では`AddStatic`、`AddRaw`、`AddOnceStatic`、`AddOnceRaw`を使い分けられ、
優先度付き登録と自動解除される購読値にも対応します。読み取り専用の対象には
`const`メンバー関数をそのまま登録できます。対象を保持する登録ではないため、
登録中の対象の生存期間は呼出し側が管理します。
同じ通知値を複数の処理へ渡すため、複数登録の引数には右辺値参照を指定できません。
値で渡す引数はコピー構築可能で、静的関数とメンバー関数は`noexcept`宣言が必要です。

`FTimerSubsystem`は既存の`FTimerManager`とサブシステム登録機構を使うワールド機能です。
`FScene`、`ANode`、`AComponent`から`GetSubsystem<FTimerSubsystem>()`で取得でき、
ワールド更新と同じ時間で自動的に進みます。ワールド終了時には登録をすべて解除します。

一度だけ呼ぶ処理は`SetTimeout`、繰り返し呼ぶ処理は`SetInterval`で登録します。
返された`FTimerHandle`を`Cancel`へ渡すと、登録した処理を解除できます。
`IsActive`は登録が残っているかを確認し、`CancelAll`は全登録を解除します。
未設定の処理、負の待ち時間、有限でない秒数は登録せず、無効な`FTimerHandle`を返します。
周期タイマーでは、これらに加えて0秒も登録しません。
世代番号を使い切った後も古いハンドルを再一致させず、新しい登録を無効なハンドルで拒否します。
更新時に負または有限でない秒数を受け取った場合も、登録状態と残り時間を変更しません。
処理から同じ管理器の`Tick`を呼んでも再入更新は行いません。更新中に登録したタイマーは、
空き枠を再利用した場合も次の`Tick`から時間を進めます。

正規の値型は`event/TimerHandle.h`、管理器は`event/TimerManager.h/.cpp`に分けています。
旧`gameframework::FSceneTimer`と`gameframework::FTimerHandle`は別実装を持たず、正規型の互換別名です。
用途を明示したい場合は`FSceneTimerHandle`も同じ正規型の別名として使えます。
旧パック形式の`Pack`、`Index`、`Gen`は廃止し、すべて同じ世代付き識別値を使います。

乱数と固定ステップは利用者ごとに再現可能な状態を持つため、共有サブシステムにはしません。
