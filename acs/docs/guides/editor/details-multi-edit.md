# `Details` の複数選択編集

3D の `Details` パネルは、2件以上のネイティブノードを1つの編集対象として扱います。先頭ノードの値を複製せず、利用者が変更した項目だけを各ノードへ適用します。

## 表示契約

- 見出しに選択件数を表示する。
- `Enabled` は3状態のチェックボックスとし、値が混在している場合は未確定状態を表示する。
- `Location`、`Rotation`、`Scale`、`Mesh Renderer Color` は成分ごとに共通値を判定し、混在値を `—` で示す。
- 入力した成分だけを変更し、未編集成分の値と `float` のビット列を保持する。
- `Reset selected transforms` は `Location` と `Rotation` を0、`Scale` を1へ戻す。

リフレクションで取得したコンポーネントは、全対象で型、スロット、プロパティー名、`kind`、`flags`、`category`、既定値のビット列が一致する場合だけ共通行として表示します。`Bool` は3状態、数値とベクトルは成分ごとの混在値、既知の `Enum` と `ObjectRef` は型付き選択肢を使用します。

`ObjectRef` の候補からは、現在選択している全ノードのIDを除外します。複数選択中のノード同士を誤って参照先にする候補は表示しません。リセット操作は、`InspectorReflectedPropertySchema.IsEditable` と `HasDefault` がともに真の場合だけ有効です。非表示、読取専用、`String`、既定値なしのプロパティーにはリセットを提供しません。

## 一括変更の契約

`InspectorMultiEditContract` は、次の順序で一括変更を行います。

1. 空、重複、不正、または古い選択を拒否する。
2. 全対象について、ノードID、コンポーネント型、スロット、プロパティー番号、現在のスキーマを最初の書込み前に再検証する。
3. 全対象の現在値を4成分の `float` として読み、有限値であることを確認して復元用に保持する。
4. 要求値を型に従って正規化し、全対象の変更内容を組み立てられた場合だけ書込みを開始する。
5. 選択順に書き込み、直後に同じ4成分を読み戻して全ビットが要求値と一致することを確認する。
6. 書込みまたは読戻しに失敗した場合は、失敗した対象を含む変更済み対象を逆順に復元する。個別の復元に失敗しても残りの復元を続け、完全に戻せなかった状態を成功として扱わない。

非有限値は最初の書込み前に拒否します。`I32`、`Enum`、`ObjectRef` は整数で絶対値が `16,777,216` 以下、`U32` は整数で `0..16,777,216` の範囲に限ります。これは `float` で整数を正確に往復できる範囲です。`Float4` の検証は表示上の近似比較ではなく、`BitConverter.SingleToInt32Bits` による4成分すべてのビット比較です。

成功した一括変更は、1件のシーンの取り消し／やり直しトランザクションになります。選択対象の識別情報を統合キーへ含めるため、異なる選択に対する編集履歴は統合しません。

トランスフォームの変更は `sparse-transform-mutation-v1` の9ビットマスクを使います。マスク外の成分は再代入せず、`Scale` の下限制限はマスク内の軸だけへ適用します。未知のマスク、非有限値、9件以外の配列は書込み前に拒否します。

## 制限

コンポーネントの追加、削除、並べ替え、マテリアルの再割当て、リフレクションで取得した `String`、`CallInEditor` メソッドは単一選択で操作します。古いシーンデータに復元不能な0付近の `Scale` がある場合、その軸の複数編集は書込み前に拒否します。

## 検証

```pwsh
AcsEditor.exe --inspector-multi-edit-selftest
AcsEditor.exe --inspector-reflected-multi-edit-selftest
```

自己検査は、全対象の事前検証、`ObjectRef` 候補の除外、リセット条件、非有限値と整数精度の拒否、`Float4` のビット読戻し、途中失敗時の逆順復元を検証します。
