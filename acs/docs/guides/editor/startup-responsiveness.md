# Editor 起動時の応答性

ACS Editor は、ネイティブホスト初期化、配置読込み、ワークスペース復元を分割し、WPF の所有スレッドが初回描画、ウィンドウ操作、入力、診断を処理できる状態を保ちます。

## ネイティブホストの作成

`EngineViewport.BuildWindowCore` は、最初に軽量な子 `HWND` と入力経路だけを作成します。DLL の読み込み、`acs_editor_abi_query`、`acs_editor_create`、初期の表示抑制は `EditorNativeBootstrap` がワーカースレッドで実行します。D3D デバイス、スワップチェーンの接続、描画は `HWND` を所有する `Dispatcher` へ戻してから行います。

`EditorNativeBootstrap` は、プロセス全体で1つのネイティブホスト枠を `EditorNativeHostLifetimeLease` として所有します。この所有権は ABI 照会と作成の前に取得し、公開済みホストまたは公開待ち結果が破棄されるまで解放しません。古い `HwndHost` 世代の作成が戻る前に新しい世代が開始しても、ログ機能、メモリ割当て機能、作業スレッド群を持つネイティブホストが同時に2つ作成されることはありません。

枠の待機は取消に対応します。待機中に世代が無効になった場合は、ネイティブ作成を呼ばずに終了します。作成後に取消された未公開ハンドルはワーカースレッドで破棄し、その後に所有権を解放します。

## 世代による公開判定

ワーカースレッドの結果は `DispatcherPriority.Loaded` で公開します。次の条件をすべて満たす場合だけ、結果のハンドルを現在の `EngineViewport` へ採用します。

- 起動処理の `CancellationTokenSource` が取り消されていないこと。
- 開始時の世代が現在の `_renderPumpGeneration` と一致すること。
- `EngineViewport` が破棄中でないこと。
- 対象の子 `HWND` が現在も存在すること。
- ABI互換性照会、ホスト作成、表示抑制が成功していること。

ウィンドウ再構築、終了、起動失敗で古くなった結果は公開しません。ハンドルを持つ古い結果は破棄し、空の結果はネイティブビューポートを無効のまま保ちます。契約版と機能ビットの条件は[Editor ネイティブ ABI](../../architecture/editor-abi.md)を参照してください。

## 配置とワークスペース

レイアウトと名前付きワークスペースのJSONは、`Loaded` 後にワーカースレッドで読み取ります。レイアウトは最大64 KiBの厳密なUTF-8で、通常ファイルだけを受理します。再解析ポイント、不正なUTF-8、読取中に長さまたは更新時刻が変わったスナップショットは適用しません。

マウス、キーボード、タイトルバー移動、サイズ変更、ワークスペース操作が読取中に発生した場合は公開世代を進めます。遅れて完了した古い世代は、ウィンドウ位置、ドック表示、ワークスペース一覧を上書きしません。

## シーン状態の取得と遅延結果

シーンの取り消し履歴と未保存判定は、`Dispatcher` 上で2Dと3Dのネイティブシリアライザーを1回ずつ呼び、1つの `EditorDocumentState` にまとめた正規取得結果を共有します。未保存判定用の指紋からは Editor の選択状態を除外します。同じ変更に対して、取り消し履歴用と未保存判定用に別々のシリアライズを行いません。

取得後に遅れて公開する未保存判定は、`SceneCanonicalCapturePublicationKey` の `DocumentId`、`MutationRevision`、`CleanBaselineGeneration`、`Use3D` が現在値と完全に一致する場合だけ受理します。さらに、未保存判定が現在も必要で、対象文書が選択中であり、描画エンジンが有効で、`Play`、`Preview`、履歴停止中ではないことを確認します。シーンの入替え、新しい変更、保存基準の更新、2D/3D切替え、文書切替え、シミュレーション開始をまたいだ結果は破棄し、通常のタイマー取得へ戻します。

## 起動モニター

```pwsh
AcsEditor.exe .\Game.acsproject --secondary-monitor
AcsEditor.exe .\Game.acsproject --monitor 0 --no-activate
AcsEditor.exe .\Game.acsproject --secondary-monitor --unattended --show-profiler
```

- `--secondary-monitor` は、利用可能な最初の非プライマリモニターを選びます。
- `--monitor N` は、プライマリを先頭に安定整列したモニター一覧の0始まりインデックスを選びます。`N` は0以上である必要があります。
- `--secondary-monitor` と `--monitor N` は同時に指定できず、同じ引数を複数回指定できません。
- 存在しないインデックスや、非プライマリモニターがない状態の `--secondary-monitor` は起動エラーです。

モニターを明示した場合は、保存済みの最上位ウィンドウ位置と最大化状態を適用せず、対象モニターの作業領域内へ非アクティブで配置します。ドック幅、パネル表示、選択中タブ、ワークスペース名は通常どおり復元します。`--no-activate` は初期フォーカスだけを抑制し、明示的なマウス操作後は通常操作できます。`--unattended` は検証中のキーボード、マウス、タッチ、ポインター、ジェスチャー、ファイルドロップを継続して拒否します。

## 操作回復

起動後のネイティブ描画は短い処理単位で `Dispatcher` へ制御を返します。古い描画世代のコールバックは `_renderPumpGeneration` で破棄します。入力の公平性と GPU 待機上限は[パフォーマンスプロファイラーのキャプチャー](profiler-capture.md)を参照してください。

ビューポートのドラッグは子 `HWND` が Win32 のポインターキャプチャーを所有します。左、右、中央ボタンの終了処理と、他ウィンドウにキャプチャーを奪われた場合の取消しは `WM_CAPTURECHANGED` に集約します。`ReleaseCapture()` が同期的に `WM_CAPTURECHANGED` を送るため、同じジェスチャーを複数の経路で終了しません。

`Dispatcher` の定期処理は、開始ボタンが物理的に離れてから750 ms以上一致しない、取り残されたキャプチャーだけを回復します。正当なドラッグ、最上位ウィンドウの移動・サイズ変更、終了処理、破棄中、古い描画世代では解放しません。解放直前に `HWND`、所有者、世代を再検証し、回復した場合は診断コード `STALE_VIEWPORT_CAPTURE_RECOVERED` を記録します。

ネイティブホストが利用できない場合はネイティブビューポートを無効化し、プロジェクト、アセット、`Project Settings` など独立した Editor 機能を維持します。

## 終了時のレイアウト保存

Editor の終了は、文書の保存確認、補助ウィンドウとネイティブサーフェスの回収、自動保存処理の終了とセッション復旧データの破棄を完了してから、レイアウト保存へ進みます。

`SaveEditorLayoutAsync()` は、最上位ウィンドウの位置、ドック寸法、表示状態、選択中タブ、ワークスペース名を `Dispatcher` 上で不変の JSON 文字列へ変換します。その後のディレクトリ作成、書込み、ディスク反映、置換、一時ファイルの掃除は専有する作業タスクで行い、終了処理はその完了を待ちます。待機中に新しいレイアウト保存世代が作られた場合は最新世代だけを公開します。保存の完了または診断可能な失敗を経てから、最終の `Close()` を許可します。

## 検証

```pwsh
AcsEditor.exe --editor-reliability-selftest
```

自己検査は、作業スレッドでの作成、取消時の未公開ハンドル破棄、プロセス全体のホスト所有権、`HwndHost` 世代の直列化、ABI 不一致時の作成拒否、モニター引数、レイアウト上限、厳密な UTF-8、再解析ポイント拒否、古い配置世代の破棄、`WM_CAPTURECHANGED` による終了、取り残されたキャプチャーの回復条件、シーン取得結果の公開境界、`Dispatcher` 外でのレイアウト保存を検証します。
