# ツールパネルのドッキング

ACS Editor は、移動可能な各ツールを安定 ID 付きの1つの `FrameworkElement` として登録します。同じパネルを複製せず、`Docked`、`Floating`、`Hidden` の3状態で所有者を切り替えます。

Editor 全体の所有権と実行境界は[ACS Editor アーキテクチャ](../../architecture/editor.md)を参照してください。

## 登録済みパネル

| ID | UI表示 | ドック |
|---|---|---|
| `hierarchy` | `Scene Outliner` | 左側 |
| `inspector` | `Details` | 右側 |
| `console` | `Console` | 下側 |
| `build` | `Build` | 下側 |
| `assets` | `Assets` | 下側 |
| `profiler` | `Profiler` | 下側 |

下側の4パネルは同じドックを共有しますが、状態と配置は個別に保持します。下側ドック全体の表示と選択中タブはワークスペースが所有し、各パネルの `Docked`、`Floating`、`Hidden` とフローティング配置はツールパネル保存領域が所有します。

下側タブを選択した場合、そのパネルが `Floating` なら再ドッキングし、`Hidden` ならドックへ復元して選択します。複数のパネルを同時に `Floating` にできます。`Ctrl+J` と `View > Bottom Dock` は下側ドック全体の表示だけを切り替え、各パネルの状態と選択中タブを変更しません。下側ドックの `Hide` ボタンは全体表示ではなく、現在選択している1パネルだけを `Hidden` にします。

## 所有権と状態遷移

`DockableToolHost` は元の `FrameworkElement` を親コンテナ間で移動します。確定後のパネルは、元のドックまたは1つの `DockableToolWindow` のどちらか一方だけに属します。`Float` または `Re-dock` の途中で切離し、接続、所有者検証に失敗した場合は、最後に確定した所有者へ戻します。失敗した `Float` はドック状態、失敗した `Re-dock` はフローティング状態を維持し、実際の所有者と表示状態を一致させます。

フローティングウィンドウを閉じた場合はパネルを破棄せず `Hidden` へ移します。レイアウト初期化は登録済み全パネルのスナップショットと選択中の下側タブを先に取得し、全パネルを既定ドックへ戻せた場合だけ確定します。途中で失敗した場合は開始時の状態へ戻します。

## 永続化

配置は `%LOCALAPPDATA%\AcsEditor\ToolPanels.v2.json` へ保存します。スキーマ版は `2`、上限は16 KiBです。登録済み6件すべての一意なID、状態、有限で到達可能なフローティング配置が必要です。未知ID、重複ID、欠落、不正な状態、未対応版を含むスナップショットは全体を拒否します。

保存は同じディレクトリの一意な一時ファイルへ書き、既存ファイルを原子的に置き換えます。非有限、最小寸法未満、画面外の配置は、パネルごとの到達可能な既定範囲へ正規化します。

有効な版2スナップショットだけを6パネルへ適用します。ファイルがない、または全体が不正な場合は、ワークスペースが復元した下側ドック全体の表示、選択中タブ、現在の各パネル状態を変更しません。その現在状態から6パネル分の版2スナップショットを作り直して保存します。不完全なファイルの一部だけを適用したり、不正な1件を理由に他の保存領域が所有する下側ドック表示を初期化したりしません。

## Editor 終了時のトランザクション

Editor終了では、文書保存の承認後に補助サーフェスを1つのトランザクションで回収します。

1. 登録済み全パネルの状態・配置と、選択中の下側タブを取得します。
2. 保存更新を抑止した状態で、全パネルを一時的に `Re-dock` します。
3. `Camera View` のネイティブサーフェスを最後の補助サーフェスとして戻します。
4. 全サーフェスが戻った場合だけトランザクションを確定し、その後に自動保存ワーカーの終了とセッション復旧データの破棄へ進みます。

パネルまたは `Camera View` を戻せない場合は終了を取り消し、パネルを逆順で復元します。完全に復元できない場合は、実際に回復できた配置を保存します。取消時はアセット操作と Editor 入力を再開し、`Material Editor` の終了承認を取り消します。成功時に保存するのは一時的な `Re-dock` 状態ではなく、トランザクション開始前のフローティング配置と選択中タブです。

開いている各 `Material Editor` は、終了準備の開始時にそれぞれの `IsEnabled` を記録し、最終の復旧処理が終わるまで入力を無効にします。終了が取り消された場合は、まだ開いているウィンドウだけを開始時の `IsEnabled` へ戻します。開始時から無効だったウィンドウを有効化せず、途中で閉じたウィンドウへ書き戻しません。終了が成功した場合は再び有効化しません。

自動保存停止後の最終終了は補助サーフェスのハンドラーを再実行しません。これにより、回復不能な状態で一部だけ再開することを防ぎます。

## パネルの追加

新しい移動可能パネルは、次の順序で登録します。

1. `ToolPanelDockingContract` に一意で永続的な ID と `AccessibleName` を追加します。
2. パネルの唯一のルート `FrameworkElement` を WPF の `Panel` に配置します。
3. `RegisterToolPanelHost` へドック表示の取得・適用コールバックとともに1回だけ登録します。下側ドックを共有する場合は `RegisterBottomToolPanel` を使用します。
4. 到達可能な既定配置を追加し、保存スナップショットの件数と ID 検証へ含めます。
5. `ToolPanelDockingSelfTest` の登録順、単一表示要素の所有、状態遷移、終了時ロールバックの期待値を更新します。

文書タブと `Camera View` のネイティブサーフェスは別の寿命契約を持つため、`DockableToolHost` へ直接登録しません。

## 検証

```pwsh
AcsEditor.exe --workspace-selftest
$image = Join-Path $env:TEMP "acs-workspace.png"
AcsEditor.exe --workspaceshot $image
```

自己検査は、安定した登録順、単一表示要素の所有、`Floating` と `Hidden` の下側タブ選択、下側ドック全体と個別 `Hide` の分離、`Float` と `Re-dock` のロールバック、版2保存領域の全体検証と現在状態からの初期化、終了トランザクション、`Material Editor` の `IsEnabled` 復元、`Camera View` 失敗時の復元、DPI 配置、負座標モニターを検証します。`--workspaceshot` は決定的なワークスペース配置を PNG へ描画します。
