# 大気のミー消散係数の経路間整合（2026-09-08）

## 対象と結論

`Sky.cpp`の物理空、`Atmosphere.cpp`のCPU評価とGPU大気表は、同じ大気モデルを使う契約を持つ。
しかしCPUと物理空では、GPU大気表が消散として扱う値を吸収と呼び、散乱を再び足していた。
今回の修正はこの解釈の不一致だけを除く。光路の分割・積分段数・位相関数・密度分布は変えない。

地表におけるミー係数をkmの逆数へ換算すると次のとおり。

| 経路 | 散乱 | 吸収 | 消散（散乱＋吸収） |
| --- | ---: | ---: | ---: |
| 修正前のCPU／物理空 | 0.003996 | 0.004400 | 0.008396 |
| 既存のGPU大気表／修正後の共通契約 | 0.003996 | 0.000404 | 0.004400 |
| Bruneton著者のデモ設定（比較用） | 0.003996 | 0.000444 | 0.004440 |

吸収が大きい媒質そのものは物理的に不可能ではない。今回確定した不具合は、同じ空であるはずの
経路が異なる媒質を計算すること。既存GPU大気表の消散0.0044を維持し、CPU／物理空をそろえた。
吸収0.000404は差から導かれる値で、見た目を明るくするために選んだ調整値ではない。
単一散乱アルベド（散乱／消散）は約0.90818となり、散乱より消散が小さくならない。

## 一次資料と採用しなかった変更

著者の[デモ初期化コード](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/demo/demo.cc.html)の
`kMieAngstromBeta / kMieScaleHeight`と`mie_scattering`／`mie_extinction`への代入を確認した。
その設定は消散4.44e-6 m⁻¹、散乱は消散の0.9倍である。ACS既存の4.4e-6とは一致しない。
著者の既定値は全ての大気に共通の物理定数ではなく、ACSの大気上端などにも差がある。
根拠を確認せず4.44へ全経路を変更することは今回行わない。

CPUはmとm⁻¹、GPUはkmとkm⁻¹を使う。係数を1000倍、距離を1/1000にすると光学的厚さは不変。
Skyの媒質関数が返す密度比と、GPU大気表が返す散乱係数は異なる量なので、そのまま比較しない。
試験ではSkyの密度比へ地表散乱係数を掛け、同じ単位へ換算した。

## TDDと試験範囲

既存の`acs_sky_ground_tests`へ追加し、新しい検証プロジェクトや公開APIは作らない。
添付の設計スキルに沿い、入力・製品計算・出力・独立参照・合否を分離する。

1. `CpuSunTransmittanceUsesSharedMieExtinction`と`ActualGpuMediumPathsUseSharedMieExtinction`を先に追加。
2. 製品変更前に実行し、旧2試験成功・新2試験失敗を記録。
3. CPUの太陽透過と単散乱内の視線透過、Skyの媒質評価から散乱の再加算を除去。
4. Debug／Releaseで新旧4試験成功を確認。
5. CPUの視線側だけ修正を忘れる回帰に備え、`CpuSingleScatterUsesSharedMieExtinction`を追加。
   この追加条件は最初の失敗試験には含まれず、補強試験として扱う。
6. 独立監査で、既存`EXPECT_NEAR`がNaNを失敗にしない問題を確認。
   新試験の実測値・参照値へ有限値検査を追加した。共通比較マクロ自体の修正は今回の対象外。
7. CPUの視線側だけ散乱の再加算へ戻す一時的な変異を実製品へ入れ、単散乱試験だけが失敗することを確認。
   直後に復元し、`Atmosphere.cpp`のSHA-256が監査済みの値と一致することを確認した。

| 試験 | 実際に評価するもの | 独立した期待値 |
| --- | --- | --- |
| CPU太陽透過 | 公開`SunTransmittanceAtAltitude`、高度0／1200／8000／10000／25000／40000m | 同じ24点の鉛直中点則を倍精度で評価 |
| GPU媒質 | 現在のSky生HLSLと大気表の共通マクロを抽出し、実行時高度から実GPU計算・RGBA32F読戻し | 7高度の指数密度、三角形オゾン分布、共通係数から計算 |
| GPU短光路 | 製品`PhysicalTransmittance`を0／0.001／1.2kmの光路長で呼出し | 同じ8点則の倍精度計算、0長は透過率1 |
| CPU単散乱 | 公開`CAtmosphere::EvaluateSkyRadiance`、鉛直上向き、視線50段・太陽20段 | 区間内の指数減衰を`expm1`で積分し、区間入口の透過率を掛ける独立計算 |
| 既存の地表境界 | 製品HLSLの交点・微小光路と、公開`CSky::Render` | 前回の境界・連続性試験を維持 |

GPUが使えない、コンパイルできない、提出・読戻しが失敗した場合は試験を失敗させる。
製品関数のコピーや、式の文字列があるだけの確認を数値合格の代用にしない。
GPU大気表の共通関数は実行するが、大気表全体の生成・補間経路をこの新試験だけで保証しない。

参照は積分段数を再現して係数の不一致を分離するもので、真の積分への収束保証ではない。
係数の許容差は2e-8 km⁻¹、短光路透過率は2e-6、CPU太陽透過率は2e-5、CPU単散乱は2e-6。
CPU太陽透過の許容差には大きい地球中心座標での単精度丸めを含む。

## 未合格の項目と次の優先課題

- 8点／24点等の固定幅中点則による長光路の積分誤差。鉛直経路では指数密度の解析積分と比較できる。
- CPUの地表交点と地表反射は前回のSky専用修正をまだ共有していない。係数の一致は幾何の一致ではない。
- 太陽円盤の照度／輝度変換、遮蔽、散乱との加算、HDR格納範囲。詳細は[地表境界と太陽の研究記録](SkyGroundBoundaryResearch.md)。
- 地上／上空／雲内の連続画像、実解像度性能、雲の厚み・形状・ちらつき、外部Framework再導入、配布物の再生成。

次は解析解と比較する光路積分の失敗試験を追加し、密度の変化に応じた区間分割や変数変換を検討する。
係数の整合性を空・雲全体の画質や商用品質の保証へ拡大しない。

係数修正後の鉛直0→100kmでは、指数密度の解析積分はレイリー約7.99997019km、ミー1.2km、
三角形のオゾン密度の積分は15kmとなる。透過率はRGBで約(0.94040389,0.86765718,0.76234657)。
同じモデルを8点中点則で計算すると、透過率を約(0.97%,1.62%,3.06%)過大評価する。
24点でも約(0.26%,0.35%,0.49%)過大評価する。これらは倍精度で求めた積分則自体の誤差で、
実GPU測定値や画像の誤差率ではない。次のTDDで実製品の出力から検証する。
