# StudioWorkflow ローカルアセットロック安全契約

`FLocalFileAssetLocking` は `<asset_path>.lock` という補助ファイルを使う、
単一ホスト上の協調ロックです。ネットワーク共有や敵対的な OS 管理者に対する
セキュリティ境界ではありませんが、通常権限の複数プロセス・スレッド間では
「取得した世代だけを解除できる」という所有権境界を提供します。

## 検証付き API

- `TryLockAsset(path, owner)` は `CREATE_NEW` でのみ取得し、成功時に 128 ビットのトークン
  と取得時刻を返します。全バイトの書き込み、`FlushFileBuffers`、`CloseHandle`
  が完了するまで成功を公開しません。
- `TryQueryLock(path, out_info)` はサイズ、完全読み取り、EOF、文法、オーバーフロー、
  クローズを検証してから `out_info` と内部照会バッファを一度に更新します。
  失敗時に呼び出し側の `out_info` は変わりません。
- `TryUnlockAsset(path, owner, token)` は所有者とトークンが両方一致するときだけ
  解除します。検証用ハンドルは `FILE_SHARE_DELETE` なしで開き、同じハンドルを
  `FileDispositionInfo` で削除待ちにします。検証後にパスが別世代へ
  すり替わり、その新しいファイルを `DeleteFileW(path)` で消す競合はありません。

従来の `LockAsset`、`UnlockAsset`、`UnlockAssetAs`、`QueryLock` は残っています。
取得は検証付き API へ委譲します。トークン引数を持たない解除 API は、同じバックエンド
インスタンスが取得時から固定長テーブルに保持しているトークンだけを使います。他プロセス
やバックエンド再生成前のロックを所有者名だけで解除することはできません。プロセスを
またいで解除する利用側は、取得結果のトークンを安全に保持して検証付き API を使います。

## 記録形式と上限

現在の正規記録は、次のバイト列と完全一致する UTF-8 テキストです。

```text
ACSLOCK/1
OWNER:<owner>
TOKEN:<32 uppercase hex digits>
TIME:<unsigned decimal UNIX seconds>
```

最終改行は必須です。次を一つでも満たす記録は
`CorruptRecord` または `RecordTooLarge` になります。

- マジック値・版、ラベル、行数、最終改行が一致しない
- 部分読み取り、余分なバイト、二つ目の記録、埋め込み NUL がある
- 所有者が空、255 バイト超、不正な UTF-8、制御文字を含む
- トークンが 32 桁の大文字 16 進数でない、または全桁が 0
- 時刻が空、10 進数以外、`u64` のオーバーフロー
- 記録全体が 512 バイトを超える

API 入力は、終端 NUL を除くパス本文が最大 1,023 バイト、所有者名が最大 255 バイトで、
厳密な UTF-8 である必要があります。パスへ `.lock` を付けた UTF-16 文字列が内部バッファへ
収まらない場合も `PathTooLong` になります。所有者名の CR/LF、NUL、制御文字
は禁止です。内部テーブルは 1 インスタンスあたり 64 ロックです。これらの上限超過は
切り詰めず、安定した `ELocalAssetLockError` 値で失敗します。

## 安全側での失敗と期限切れの扱い

既存の補助ファイルは、内容が破損・旧形式・古い時刻であってもロック済みとして扱います。
この API は PID 生存確認や時刻だけを根拠に自動削除しません。そうした推測は、遅延中の
正当な所有者や別プロセスが再取得したロックを消す危険があるためです。

期限切れまたは破損したロックの復旧は、運用者が所有プロセスの停止、対象パス、記録内容、
バックアップを確認した後に行う管理操作です。通常の解除 API に強制削除は
ありません。旧 2 行形式は自動変換せず、管理確認後に削除して再取得します。

## エラーと回復

`ELocalAssetLockError` の数値 1500–1519 はログ・テレメトリ向けの安定値です。
代表的な分類は次のとおりです。

| 分類 | 意味 | 安全な対応 |
|---|---|---|
| `AlreadyLocked` | `CREATE_NEW` が既存ファイルを検出 | 照会して所有者を表示し、待機する |
| `OwnerMismatch` / `TokenMismatch` | 別の所有者または別取得世代 | ファイルを削除せず、最新トークンを再確認する |
| `CorruptRecord` / `RecordTooLarge` | 非正規、部分読み取り、後続データ、オーバーフロー | ロック済みの扱いを保って管理者へ通知する |
| `NotOwned` / `CapacityExceeded` | インスタンスの追跡境界 | 検証付き API のトークンを使う、または取得数を減らす |
| `WriteFailed` / `FlushFailed` / `CloseFailed` | 永続化完了を証明できない | 成功扱いにせず、補助ファイルを調査する |
| `DeleteFailed` | 同一ファイルハンドルの削除待ち化に失敗 | 所有権を保持したまま再試行する |

取得中の書き込み・フラッシュ失敗では、まだ開いている取得ハンドル自身を
削除待ちにしてから閉じます。パス名による後始末は行わないため、
後始末と別プロセスの再取得が競合しても他世代を削除しません。

## テスト観点

`tests/studio_workflow_safety_tests.cpp` は検証付き API の往復、既存ファイル、
不一致の所有者・トークン、旧形式、部分読み取り、埋め込み NUL、後続データ、時刻のオーバーフロー、
記録・パス・所有者の上限、失敗時の出力不変、2 スレッドの同時 `CREATE_NEW` で成功者が
一人だけになることを固定します。
