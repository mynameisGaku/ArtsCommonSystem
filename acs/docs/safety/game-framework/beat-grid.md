# FBeatGrid のホールドノートと安全契約

`FBeatGrid` は譜面をコピー所有し、有限値の再生時計を進め、譜面の各ノートに
1 回だけ判定を発行します。検証付き API は取り込みデータやユーザー作成データ向けで、
既存ゲームコードのために従来のラッパーも残します。

## ホールドノートの寿命

ホールドノートは全体で 1 つの採点単位です。

1. `PressLane(lane)`（または互換別名の `Tap(lane)`）は、指定レーンにある未判定かつ
   非アクティブなノートを探す。
2. 通常ノートは直ちに確定する。
3. ホールドノートは先頭判定を保存してアクティブになる。この時点ではスコア、コンボ、
   判定コールバックを発行しない。
4. `ReleaseLane(lane)` は末尾（`time_sec + hold_duration_sec`）が最も近いアクティブなホールドノートを選ぶ。
5. 末尾の `Good` 判定時間幅内で離すとノートを確定し、先頭と末尾の悪い方を最終結果にする。
6. 判定時間幅より早い解放は `Miss`。`tail + good_window` を過ぎてもアクティブなノートは
   `Tick` 中に Miss になる。

すべての完了経路はコールバックを呼ぶ前にアクティブ状態を消し、ノートを判定済みにします。
押下、解放、Tick を繰り返しても同じノートを再度加点しません。ホールドノートは合計数と精度で
1 ノートと数えます。

押下と解放の呼び出しは状態の変化点として扱います。判定したい物理的な解放ごとに
`ReleaseLane` を 1 回送る必要があります。一時停止中は時計を止めますが、停止時刻に
一致する入力は受理し、従来の `Tap` 挙動を維持します。

## 決定的な衝突解決

譜面は入力順を保持し、内部で並べ替えません。

- 距離が等しい未判定ノートは譜面番号が最小のものを選ぶ。
- 距離が等しいアクティブなホールドノートの末尾も譜面番号が最小のものを選ぶ。
- 1 回の `Tick` は期限切れノートを譜面入力順に処理する。

重なるホールドノートも利用できます。`ActiveHoldCount()` は総数を返し、
`IsLaneHolding(lane)` はレーンに 1 個以上のアクティブなホールドノートがあるかを返します。

## 検証付き譜面読み込み

次のように結果を確認します。

```cpp
const auto result = grid.TryLoadChart(notes, count, bpm);
if (result != acs::game::EBeatChartLoadResult::Success) {
    ACS_LOG_ERROR("ビートチャート読み込み失敗: %s",
                  acs::game::BeatChartLoadResultName(result));
}
```

`TryLoadChart` は入力全体を検証し、3 個の一時配列の容量を確保して譜面をコピーした後
だけ公開中の譜面を置き換えます。エラー時は以前の譜面、再生状態、統計、コールバックを
維持します。

受理する上限は公開定数です。

| 項目 | 契約 |
|---|---|
| ノート数 | `0 .. kMaxBeatChartNotes`（65,536） |
| BPM | 有限値、`0 .. kMaxBeatBpm`（1,000） |
| ノート時刻 | 有限値、`0 .. kMaxBeatChartTimeSec`（24 時間） |
| レーン | 6 個の `EBeatLane` 値のいずれか |
| ホールド時間 | 有限かつ非負、最大 1 時間 |
| ホールド末尾 | `kMaxBeatChartTimeSec` 以下 |

ホールドノートの継続時間は厳密に正でなければなりません。通常ノートの継続時間は範囲内なら
受理し、0 へ正規化します。`nullptr` は空譜面の場合だけ有効です。

`LoadChart` は互換ラッパーです。結果を無視しますが、不正入力や確保失敗で
以前の譜面を部分的に消去せず、そのまま維持します。

## 判定時間と数値安全性

`TrySetTimingWindows` は有限、昇順、非負で `kMaxBeatTimingWindowMs` 以下の
ミリ秒値だけを受理し、失敗時は状態を変更しません。互換用
`SetTimingWindows` は有限値を範囲制限して昇順へ直し、非有限値を無視します。

`Tick` は次を無視します。

- 0 以下の時間差。
- NaN または無限大。
- 加算すると `f32` 再生時計がオーバーフローする有限の時間差。

拒否した Tick は時刻、ホールド状態、判定、スコア、イベントを変更しません。

## コールバックの安全性

判定状態は `FJudgeCallback` を呼ぶ前に反映します。元の `FBeatGrid` 契約との
互換性のため、`FBeatEndCallback` は最後の通常ノート押下またはホールドノート解放の直後
ではなく、次の有効な `Tick` まで遅延します。終了状態はコールバック前に反映し、
正確に 1 回だけ発火します。

コールバックはグリッドの置換、初期化、停止、消去を行えます。版番号ガードにより、
実行中の `Tick` は古い譜面番号へ触れる前に停止します。このクラスは引き続き
単一スレッド専用であり、コールバックから別スレッドと同時に同じグリッドへアクセスしては
いけません。

## テスト範囲

`tests/beat_grid_hold_safety_tests.cpp` は次を検証します。

- 通常ノートの即時判定と終了コールバック遅延の互換挙動。
- ホールドノートの遅延採点と先頭・末尾結果の結合。
- 早期解放と未解放の時間切れによる `Miss`。
- 判定・終了コールバックが正確に 1 回だけ呼ばれること。
- 同時ノートの入力順解決。
- 有限値、範囲、レーン、件数の検証と安定診断。
- アロケーター注入による確保失敗時のトランザクション。
- 不正またはオーバーフローする時間差で状態を変更しないこと。
- 判定時間幅更新のトランザクション。
- `Miss` 走査中のコールバックが `ClearAll` する場合。
