# FScene3D テキストシリアライズ

`Scene3DSerialize` は `FScene3D` の `ANode` 階層、`FTransform3D`、
`AMeshComponent3D`、マテリアル、反射コンポーネント、および明示的なゲームカメラを
行ベースのテキストから復元する。保存 API が出力する従来の `N3D` / `MSH3D` 形式に加え、
エディタの `ACS3D v2` を互換アダプタとして直接読み込める。

パッケージ内の正準起動パスは 2D / 3D とも `main.acscene` である。拡張子でシーン種別を
決めず、内容の厳密なヘッダー (`ACSCENE v1` / `ACS3D v2`) で対応アダプタを選ぶ。
元アセットの永続 ID はパッケージマニフェストに保持される。

## 公開 API

- `TrySaveScene3DText` はシーン全体を検証・計測してから出力する。結果の
  `FScene3DSaveResult` にはエラー、終端 NUL を含む必要容量、書込文字数、ノード数、
  メッシュパス数、カメラ数が入る。`out=nullptr, cap=0` はサイズ照会になる。
- `TryLoadScene3DText` は明示された入力サイズ内を完全に解析し、全行の検証と作業領域の
  確保が成功した後だけ既存シーンを置き換える。結果の `FScene3DLoadResult` にはエラー、
  消費バイト数、エラー行、宣言ノード数、メッシュパス数、読み込み済み依存数、カメラ数、
  有効指定数、および決定的に選択されたカメラ状態が入る。
- `TryLoadScene3DFile` は個別シーンを読み、相対メッシュまたはマテリアル参照をシーンの
  親ディレクトリ基準で解決・検証してから適用する。
- `TryLoadScene3DAssetPack` は既定でパック内の `main.acscene` を読み、同じパックだけから
  依存を解決する。マウント後の欠損、CRC、解凍、デコード失敗では個別ファイルへ切り替えない。
- `SaveScene3DText` / `LoadScene3DText` は既存呼び出し向けの簡易 API として残る。
  新規コード、ファイル入力、ネットワーク入力ではサイズ付き `TryLoadScene3DText` を使う。
- `Scene3DSerializeErrorName` はログやテレメトリ向けの安定した ASCII 名を返す。

## 対応フォーマット

### 従来互換の保存形式

- ヘッダー無しの `N3D` / `MSH3D` / `CAM3D`。カメラ付きグラフを
  `TrySaveScene3DText` → `TryLoadScene3DText` で往復してもカメラを失わない。
- ルートは `id=0, parent=-1` の 1 件だけ。
- ID は 0 から連続し、子の `parent` は必ず先に宣言された ID を参照する。

### エディタ互換 `ACS3D v2`

- 先頭行は大文字小文字も含めて正確に `ACS3D v2`。
- ノード ID は一意な非負整数であれば疎でもよい。`parent` は先に宣言されたノードを参照する。
- `parent=-1` の最上位ノードを複数保持でき、実行時には 1 つの合成ルート配下へ接続する。
- `N3D`、`MSH3D`、`FLG3D`、`EMPTY3D`、`MAT3D`、`CMP3D`、
  `CPROP3D`、`CAM3D`、`SEL3D` を扱う。
- `MAT3D` は従来の金属度と粗さ、または `.acsmat` パスを扱う。
- `CMP3D` は反射ファクトリーで事前生成し、`CPROP3D` を適用してからノードへ取り付ける。
- `CAM3D <nodeId> <stableId> <projection> <priority> <active> <fovYDeg>
  <orthoHeight> <near> <far>` は既存ノードへ 1 件のカメラを取り付ける。`projection` は
  `Perspective=0`、`Orthographic=1`、`active` は `0` または `1`。
- `SPR3D`、`PLY3D`、`PFAB3D` と未知命令は、黙って欠落させず明示エラーで安全側に失敗する。

## 共通の検証規則

- 深度上限は `ANode` と同じ 512、ノード上限は 65,536、入力上限は 4 MiB。
- 1 行は 4,095 バイト、名前は 127 バイト、メッシュまたはマテリアルパスは 299 バイトまで。
- プリミティブは `-1` または `EMeshPrimitive3D` の `0..3` のみ。
- 変換と色は有限の `f32` だけを受理する。整数範囲外、`NaN`、`Inf`、途中で
  切れた数値、未知行、埋め込み NUL はエラーになる。
- `MSH3D` は既出の `Mesh` ノードに1件だけ指定できる。
- カメラは最大 256 件、安定 ID は 64 バイトまでの正準 ASCII で、ノードと安定 ID の重複を
  拒否する。投影値、優先度、FOV、平行投影の高さ、前方面と後方面は有限かつ範囲内でなければ
  ならない。複数の有効指定は入力として保持するが、選択は有効指定、優先度の降順、
  安定 ID の昇順、ノード ID の昇順で決定する。
- 保存時は明示スタックと訪問中・完了の訪問表を使い、C++ 呼び出しスタックを
  消費せずに循環と共有子・重複参照を区別して拒否する。

## トランザクション性

容量不足を含む保存前検証エラーでは出力バッファを変更しない。読み込みは全入力を固定上限内で
解析し、親関係・深度・値・文字列・命令・反射型を検証する。ファイルまたはパックの API はさらに全メッシュと
マテリアル依存を読み、デコードを完了してから反映する。したがって入力破損、未対応命令、
欠損依存、CRC/解凍/デコード失敗では読み込み先の既存シーンを変更しない。

呼び出し中に別スレッドからシーンを変更することはサポートしない。保存の計測後に内容が変化した
場合は `scene_changed_during_save` を返す。

## 生成とノード登録

`FScene3D::TrySpawn` は親が同じシーンのプールとルートツリーの両方に属することを確認する。
新規ノードを `FNodePool` へ仮登録してから `ANode::TryAddChild` を呼び、破棄予定の親や
深度上限で取り付けが拒否された場合は登録を取り消す。失敗時はツリー、有効スロット数、
既存ノードの ID を変更しない。互換用 `Spawn` は成功時に従来どおりノード参照を返し、失敗時は
安全な親またはルート番兵を返す。

`FNodePool::TryRegisterExistingNode` は、同じプールへの二重登録を既存 ID 付きで報告し、別プールの
有効 ID を持つノードは拒否する。互換用 `RegisterExistingNode` は同一プールへの重複呼び出しを
冪等に扱う。親を破棄した場合は子孫自身の破棄待ちフラグが立たなくても所有関係とともに
破棄されるため、`PurgePendingDestroy` は祖先列も確認し、親と全子孫のハンドルを回収前に
古い参照として無効化する。

## スタンドアロン3Dランタイム

`FLegacyScene3DAdapter` は互換入力を正準 `ANode` グラフへ復元し、プリミティブまたは
デコード済みメッシュを `CPbrShader` で描画する。表示・有効状態、階層変換、
PBR / Substrate マテリアル、霧を反映し、個別ファイルとパックの双方を同じ読み込み契約で扱う。

各 `CAM3D` はグラフ所有の `ACameraComponent3D` になり、姿勢は所有ノードの現在のワールド
変換から更新される。実行時は安定 ID またはノード ID でカメラを安全に切り替えられる。
投影方式はシーン全体の固定属性ではなく、各カメラが透視投影または平行投影を選択する。
パッケージマニフェストの `sceneBootstrap.adapterProjectionHint` は旧形式を取り込むための
参考値にすぎず、実行時カメラを上書きする正本のシーン属性ではない。
