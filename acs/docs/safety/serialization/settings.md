# FSettings 永続化の安全契約

`FSettings` のファイル形式は、UTF-8バイト列の
`<tag>:<key>=<value>\n` です。`tag` は `f`、`i`、`b`、`s` の4種類です。
外部入力を直接オブジェクトへ反映せず、`TryLoad` と `TrySave` を永続化境界として
使用します。既存の `Load` / `Save` は互換ラッパーとして残り、検査付き API の
エラー番号を `FErrorCode::subcode` にそのまま伝えます。

## 読み込み契約

`TryLoad` は次の順序で処理します。

1. 読み取り専用ハンドルを `FILE_SHARE_READ | FILE_SHARE_DELETE` で開く
2. サイズ上限と完全な読み取り、EOF、`CloseHandle` を確認する
3. 埋め込み NUL、行長、構文、型、値、件数を全件検証する
4. 別の `TArray<FString>` と `TArray<FEntry>` に全件構築する
5. 失敗しないムーブ代入だけで 2 配列を反映する

1 から 4 のどこで失敗しても、既存の項目、文字列プール、容量、および
`GetString` が以前返したポインタは一切変更されません。空ファイルだけは正常な
「空の設定」として反映されます。

同名キーは、型が異なる場合を含めて `DuplicateKey` で拒否します。「最後の値を採用」
にはしません。破損や人手編集の誤りを黙って隠さず、入力順に依存しないためです。
コメントは先頭バイトが `#` の行、空行は長さ 0 の行だけを許可します。未知タグや既知タグの
不正値は読み飛ばさずエラーにします。

値の規則は次のとおりです。

- `i`: 10進の符号付き整数だけを許可し、`i32` 範囲外を拒否
- `f`: 符号、小数点、10進指数の厳密な文法だけを許可し、末尾の余分な文字列、NaN、Inf、
  オーバーフロー、アンダーフローを拒否
- `b`: 小文字の `true` または `false` だけを許可
- `s`: CR/LF と埋め込み NUL を拒否
- キー: 空、`=`、CR/LF を拒否

## 上限

| 項目 | 上限 |
|---|---:|
| ファイル・保存出力 | 4 MiB |
| 項目数 | 4,096 |
| 1 行 | 4,096 バイト |
| キー | 255 バイト |
| 文字列値 | 4,096 バイト |
| 整数または浮動小数点数の入力表現 | 96 バイト |

上限はファイルを確保する前、または段階的な文字列追加の前に検査します。
加算は残容量との差分で判定し、`usize` の周回による過少確保を避けます。

## 保存契約

`TrySave` は全項目を先に検証してから、上限付き `TryAppend` で文書を作ります。
非有限の浮動小数点数、`nullptr` の文字列、長すぎる値、改行を含む値など、読み戻せない状態は
ファイル I/O の前に拒否します。

保存は保存先と同じディレクトリに
`<path>.tmp.<pid>.<tid>.<serial>` を `CREATE_NEW` で作成します。衝突時は別の連番で
最大 32 回再試行するため、別プロセスの一時ファイルを切り詰めません。全バイトの書き込み、
`FlushFileBuffers`、`CloseHandle` が成功した後だけ保存先を置換します。通常は
`MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`、保存先を読み取り側が
`FILE_SHARE_DELETE` で保持している場合は
`FileRenameInfoEx` に実装内の
`kRenameReplaceIfExists | kRenamePosixSemantics` を指定します。

最終置換より前の失敗では既存ファイルは不変です。一時ファイルは可能な範囲で削除
します。最終置換が成功した後は、古い読み取り側は従来のファイルオブジェクトを読み続け、新しい
読み取り側は新しい完全な文書を読みます。

## エラー診断

`FSettingsPersistenceResult` は次を返します。

- `Error`: 数値を再利用しない安定した `ESettingsPersistenceError`
- `Line`: 構文または値エラーの 1 始まり行番号。ファイル I/O では 0
- `Entries`: 検証と構築に成功した件数
- `OsError`: Win32 API 失敗時の `GetLastError`

ログには `SettingsPersistenceErrorName` の固定名を使用できます。エラー列挙へ値を
追加するときは末尾へ追加し、既存の数値を変更または再利用しないでください。
