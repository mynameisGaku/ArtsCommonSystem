# FSaveArchive 安全性契約

`FSaveArchive` は `.acssave` の固定ヘッダー、データ本体、CRC32 を扱う低レベル API です。
外部入力を直接扱うため、成功時だけ状態を反映するトランザクション境界として設計されています。

## ファイル形式

すべてリトルエンディアンです。

| 位置 | サイズ | フィールド | 内容 |
| ---: | ---: | --- | --- |
| `0x00` | 8 | マジック値 | `ACSSAVE\0` |
| `0x08` | 4 | バージョン | 呼び出し側が管理するスキーマバージョン |
| `0x0C` | 8 | `payload_size` | データ本体のバイト数 |
| `0x14` | 4 | `crc32` | データ本体の CRC-32 |
| `0x18` | N | データ本体 | 保存対象のバイト列 |

`payload_size` は実ファイルサイズからヘッダー 24 バイトを除いた値と完全一致する必要があります。
短いファイルだけでなく、データ本体の末尾へ余分なデータが付加されたファイルも拒否します。

## ファイル全体の検証

### `FSaveArchive::ValidateFile`

`ValidateFile` はデータ本体を呼び出し側へ公開せず、`.acssave` 全体が有効かを検証する API です。
一つの読み取りハンドルを保持したまま、次の順序で検証します。

1. パスが null または空でなく、終端 NUL を除いて 32,767 文字以下であること
2. ファイルが固定ヘッダー 24 バイト以上で、マジック値が `ACSSAVE\0` であること
3. `payload_size` が 256 MiB 以下であること
4. 実ファイルサイズが `24 + payload_size` と完全一致すること
5. データ本体を 64 KiB 単位で末尾まで読み取れること
6. 計算した CRC32 がヘッダーの `crc32` と一致すること
7. 読み取りハンドルを正常に閉じられること

データ本体の検証には固定 64 KiB のスタック領域を使います。非信頼の `payload_size` に比例する
ヒープ確保は行いません。成功時は `FSaveArchiveMetadata` の `Version`、`PayloadSize`、
`PayloadCrc32` を返します。`ValidateFile` はバージョンの採否を決めないため、特定バージョンの
読み込みには `ReadFromFile` を使います。

読み取りハンドルは `FILE_SHARE_READ | FILE_SHARE_DELETE` で開きます。検証中に同じパスが
原子的に置換されても、開いているハンドルは置換前の一つのファイルオブジェクトを参照し続けます。

## 読み込み契約

`ReadFromFile` は次の検証を完了した後にだけ `out_payload` を変更します。

1. マジック値と固定ヘッダー長
2. データ本体の 256 MiB 安全上限
3. 申告サイズと実サイズの完全一致
4. スキーマバージョン
5. 出力容量
6. データ本体の完全読み込み
7. CRC32
8. ファイルハンドルの正常終了

データ本体は検証用の一時領域へ読み込まれます。CRC 不一致、途中 EOF、確保失敗など、
どのエラーでも呼び出し側の既存オブジェクトやバッファは部分変更されません。

バージョン不一致と容量不足では、移行や再確保に使えるよう `out_payload_size` に検証済みの
データ本体サイズを返します。ヘッダーやサイズ整合性を検証できなかった場合は 0 のままです。

## 書き込み契約

`WriteToFile` は最終パスを直接切り詰めません。

1. 最初に `<path>.tmp.<pid>.<tid>` を `CREATE_NEW` で同一ディレクトリに作成し、衝突時は `<path>.tmp.<pid>.<tid>.<serial>` として最大 8 候補を試す
2. ヘッダーとデータ本体を完全書き込み
3. `FlushFileBuffers`
4. `CloseHandle`
5. `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH`を指定した`MoveFileExW`で最終パスを置換
6. 旧ファイルを開いた読み取り側が置換を妨げる環境では
   `kRenameReplaceIfExists | kRenamePosixSemantics`を設定した`SetFileInformationByHandle`へ切り替える

置換より前に失敗した場合、既存の保存ファイルは保持されます。失敗した一時ファイルは
可能な範囲で削除されます。同一ディレクトリを使うため、最終置換はボリュームを跨ぎません。
`CREATE_NEW` により、既存の一時ファイルや再解析ポイントを追跡して切り詰めることもありません。
読み込みハンドルは `FILE_SHARE_DELETE` を許可するため、読み込み中のハンドルは置換前の一貫した
ファイルオブジェクトを参照したまま、並行する原子的な置換を妨げません。POSIX 置換方式が未対応の
Windows またはファイルシステムでは安全に I/O エラーを返し、既存ファイルを保持します。

## 安全上限と診断

| 補助コード | 意味 |
| --- | --- |
| `kSubBadMagic` | マジック値不一致、または固定ヘッダー未満 |
| `kSubFileNotFound` | 読み込み対象のファイルまたは親パスが存在しない |
| `kSubMigrationNeeded` | バージョン不一致 |
| `kSubBufferTooSmall` | 出力容量不足 |
| `kSubChecksumFail` | CRC32不一致 |
| `kSubPayloadTooLarge` | データ本体が 256 MiB 上限を超過 |
| `kSubSizeMismatch` | 申告したデータ本体サイズと実ファイルサイズが不一致 |
| `kSubPathTooLong` | 通常の読み書きパスまたは `TSaveSlot::TryInit()` の入力が 32,767 UTF-16 コード単位を超過、あるいは原子的な書き込み用の接尾辞を含めると Win32 上限を超過 |
| `kSubAllocationFailed` | トランザクション読み込みまたは原子的な書き込みパス用一時領域の確保失敗 |
| `kSubInvalidArgument` | null のパス、データ本体、出力など API 事前条件違反 |
| `kSubIoError` | Win32 I/O、書き出し、終了、原子的な置換の失敗 |

呼び出し側は `FErrorCode::subcode` を分岐に使い、`os_error` がある場合は診断ログへ残してください。

## 上位APIへの伝播

### TSaveSlot

`TSaveSlot<T>` は `T` が単純コピー可能で、256 MiB 上限以下であることをコンパイル時に
検証します。読み込み補助関数は型サイズと同じ一時バッファーへ読み、アーカイブ検証と型サイズ完全一致の
後にだけ対象へコピーします。小さい旧スキーマを大きい型へ読み込んだ場合も、失敗時に対象オブジェクトの
先頭だけが更新されることはありません。

#### 生のメモリ配置の境界

`TSaveSlot<T>`は`T`のアドレスから`sizeof(T)`バイトをそのまま保存し、読み込み時も同じサイズを`MemCopy`します。`trivially copyable`の確認はコピー可能性だけを保証し、次の内容を保存形式へ変換しません。

- ポインターが指すデータと、別の実行時にも有効な参照表現
- コンパイラー、構成、ABIで変わり得るパディング
- データ本体内の整数や浮動小数点数のエンディアン形式
- 可変長配列の要素数と要素、文字列の符号化と長さ
- 型の各フィールドが持つ意味や範囲

呼び出し側は、固定幅のフィールドと明示的に初期化したバイトだけで安定したデータ本体を定義する必要があります。ポインターや可変長データを含む場合は、位置や長さを持つ独自スキーマへ変換してから`FSaveArchive`へ渡します。フィールド、パディング、エンディアン形式、文字列表現、要素数、意味のいずれかを変える場合はバージョンを更新し、`kSubMigrationNeeded`から旧バージョンを読み替える分岐を用意します。

バージョン不一致、CRC 不一致、データ本体上限、確保失敗などの `FSaveArchive` 補助コードはそのまま
伝播します。スロット未初期化は従来どおり 100 番台の固有診断です。削除は競合による
`ERROR_FILE_NOT_FOUND` / `ERROR_PATH_NOT_FOUND` もべき等成功として扱います。

#### 初期化とパス所有

`TSaveSlot<T>` には二つの初期化方法があります。

| API | パスの所有 | 呼び出し側の責務 |
| --- | --- | --- |
| `Init` | 非所有 | 渡した文字列をスロットより長く生存させる |
| `TryInit` | スロットがコピーを所有 | 呼び出し後に元の文字列を変更または破棄できる |

`TryInit` は null、空、32,767 文字超過を確保前に拒否します。検証済みのパスは一時の
`TArray<wchar_t>` へ終端 NUL とともにコピーし、確保とコピーが完了した時だけ現在のパスと交換します。
メモリ不足では `kSubAllocationFailed` を返し、以前のパスポインターと所有状態を変更しません。
確保器を受け取るコンストラクターは、この所有領域にも同じ確保器を使います。

`IsPathOwned()` は現在のパスが `TryInit` による所有コピーかを返します。`Init` で別のパスを
設定すると、それまで所有していた領域を解放して非所有モードへ移ります。

### FProgression

`FProgression` はさらに厳しい領域固有の制約を持ちます。

- マイルストーンは最大 4096 件
- データ本体長は `8 + count * 16` と完全一致
- `achieved` は 0 または 1、詰め物領域は 0、未達成時刻は 0
- 同じ FNV-1a ハッシュの重複項目と登録時のハッシュ衝突を拒否
- 保存サイズ計算、データ本体と準備領域の確保は検査付き処理

読み込みでは XP と全マイルストーン状態を別バッファーへ準備し、全項目の検証後にだけ一括反映します。
バージョン、CRC、内部スキーマ、重複、メモリ不足のどの失敗でも現在の進捗は変化しません。
アーカイブ由来の補助コードはそのまま伝播し、`FProgression` 内部スキーマ固有の診断は
`EProgressionPersistenceSubCode` の 200 番台を使います。
