# FAnimationCurve の安全な更新・評価

`FAnimationCurve` はエディター、アセットローダー、実行時アニメーションから同じキー列を受け取る。
入力元が増えても壊れたキーが内部の並び順の不変条件を破らないよう、検査付き API と
一括反映契約を提供する。

## 検証付き API

- `TryAddKey`
- `TryAddKeyHermite`
- `TrySetKeys`
- `TrySetEasingPreset`
- `TrySetWrapModes`
- `TryEvaluate`

既存の `AddKey`、`AddKeyHermite`、`Evaluate` は互換ラッパーとして残る。
不正な従来の追加操作は何もせず、評価不能な従来の評価操作は安全な `0` を返す。
詳細な回復処理が必要な呼び出し元は `FAnimationCurveResult` の安定した
`EAnimationCurveError` を使う。

## キーの不変条件

- キー数は最大 65,536
- 時刻、値、入出力接線はすべて有限値
- 補間方式と範囲外方式は定義済み列挙値のみ。従来の設定関数へ渡した不正値では何もしない
- 一括取り込みの時刻は厳密な昇順
- 同一時刻は一括取り込みではエラー、単一追加では既存キーの更新

非有限時刻を内部配列へ入れないため、二分探索の全順序が保たれる。
不正な列挙値を補間分岐の代替処理に流さず、入力境界で診断する。

## トランザクションによる一括取り込み

`TrySetKeys` は全キーと範囲外方式を先に検証し、同じアロケーターを使う一時配列へ
全量を準備する。検証または確保が失敗した場合、既存キー、前方と後方の範囲外方式を
変更しない。準備完了後のムーブ反映は確保を伴わない。

`TrySetEasingPreset(type, sample_count)` は型付きイージングを `[0,1]` の線形キー列へ
変換する。33 種類すべてに対応し、`Back` / `Elastic` の行き過ぎも保持する。
標本数は 2〜4,096 で、既定は 65。無効な型、不正な標本数、メモリ不足、評価失敗では
既存キーと範囲外方式を変更せず、成功時は前後の範囲外方式を `Clamp` へ正規化する。
AnimCurve Editor のプリセット選択もこの API だけを通して曲線を置換する。

`FAnimationCurve(FAllocator&)` によりサブシステム固有のアロケーターと決定的なメモリ不足
失敗注入を利用できる。曲線が保持する配列は、そのアロケーターで最後まで解放される。

## 検証付き評価

`TryEvaluate` は非有限時刻を拒否し、補間結果がオーバーフローして非有限になった場合は
`ResultOutOfRange` を返す。失敗時は呼び出し側の出力値を変更しない。これにより NaN が
カメラ、UI、物理演算など後段の状態へ伝播するのを防ぐ。

範囲外処理後の時刻、区間幅、区間内の正規化値も補間前に有限性を検証する。
この検証は `Step` 補間にも適用され、範囲外処理の減算や `PingPong` の周期計算がオーバーフロー
した場合に、左キーの有限値を返して成功扱いになることを防ぐ。

## テスト観点

`animation_curve_safety_tests.cpp` は並び順を保つ挿入、同一時刻更新、重複、非有限値、
不正な列挙値、メモリ不足時の状態不変、評価のオーバーフロー、従来 API の安全な無処理に加え、
全 33 種類のイージングプリセット、標本数境界、プリセット設定中のメモリ不足時の取り消しを検証する。
