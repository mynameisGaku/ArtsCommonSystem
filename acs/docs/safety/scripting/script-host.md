# FScriptHost 外部入力・実行安全性

`FScriptHost` はファイル、メモリ上のソース、関数引数、ネイティブ関数登録を
スクリプト VM へ渡す境界です。VM を呼ぶ前の検証と、VM 失敗時の呼び出し側状態保持を
この層で共通化します。

## ソースの契約

- `LoadAndRunSource` は長さ付きソースを受け取る。
- ソースは最大 64 MiB。
- `source_len > 0` の null ポインターと埋め込み NUL を拒否する。
- チャンク名は 255 バイト以下の NUL 終端文字列に限定する。
- 検証失敗時は VM を呼び出さない。
- バックエンド失敗時だけエラーコールバックを呼び出す。

`LoadAndRun(file_path)` は同じ検証付き経路へ委譲します。ファイルは
`FILE_SHARE_DELETE` 付きで開き、完全読み取り後にサイズと EOF を再確認し、ハンドルを正常に
閉じてから VM を呼びます。読み込み中の伸長・短縮、途中 EOF、クローズ失敗、確保失敗では
ソースを実行しません。パスは空を拒否し、最大 1,023 UTF-16 コード単位です。

## 呼び出しの契約

`CallGlobalFunction` は次を VM 呼び出し前に検証します。

- 関数名は 1〜127 バイト
- 引数は最大 1,024 個
- 文字列引数の合計は最大 1 MiB
- 列挙範囲外の値種別と null 文字列を拒否

戻り値は一時値へ受け、バックエンド成功後にだけ `ret_out` へ反映します。バックエンドが失敗前に
一時戻り値を書いても、呼び出し側の既存値は変化しません。

## ネイティブ関数登録簿の契約

ネイティブ関数名は 1〜127 バイト、1 ホストの登録数は最大 4,096 件です。新規追加と既存の
同名上書きは、内部キャッシュへ仮登録した後にバックエンドへ登録します。バックエンドが拒否した場合は
追加を削除、または既存項目を復元し、キャッシュを完全に元へ戻します。

`TryGetRegisteredNative` でキャッシュの関数とコンテキストを診断や動的差し替えの準備に利用できます。
関数名は項目内へ複製するため、呼び出し側の一時バッファ寿命には依存しません。
バックエンドには同期登録中だけ参照可能な名前を渡し、バックエンド側が必要なら複製します。

## 安定した診断

| サブコード | 意味 |
| --- | --- |
| `kSub_FileTooLarge` | ソースまたはファイルが 64 MiB 超過 |
| `kSub_Io` | オープン、読み取り、EOF 確認、クローズの失敗 |
| `kSub_AllocationFailed` | ソースまたは登録簿の確保失敗 |
| `kSub_FileChanged` | 読み取り中にファイル長が変化 |
| `kSub_EmbeddedNul` | ソースに埋め込み NUL |
| `kSub_InvalidPath` | ファイルパスが null、空、長すぎる、未終端 |
| `kSub_InvalidName` | 空、長すぎる、未終端の名前 |
| `kSub_ArgumentLimit` | 引数数または文字列合計上限超過 |
| `kSub_RegistryLimit` | ネイティブ関数の登録数上限超過 |

回帰テストは `tests/script_host_safety_tests.cpp` にあり、ソースの事前拒否、コールバック、
戻り値の一括反映、ネイティブ関数キャッシュの復元、名前上限、ファイル入力を検証します。
