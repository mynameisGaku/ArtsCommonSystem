# AssetPack マニフェストとレジストリの安全性

この文書は `.acpak` v1 の検証付き永続化境界と、`CAssetRegistry` が使う
ローダー登録境界を定義します。

## アーカイブ反映契約

`CAcpakWriter::Open()` は出力先アーカイブを切り詰めません。出力先ディレクトリに
`CREATE_NEW` で一意な一時ファイルを作り、`Finalize()` は次の順で処理します。

1. データ本体と完全なマニフェストを書く。
2. 再試行で残り得る古いバイト列を切り詰める。
3. 正準ヘッダーを書き直す。
4. `FlushFileBuffers` を呼ぶ。
5. 開いたままの一時ファイルを置換と POSIX 方式の
   `FileRenameInfoEx` で公開する。
6. 公開済みハンドルを閉じる。

手順 6 より前の失敗では既存出力を変更しません。`Close()` またはデストラクターは、
未公開の一時ファイルを削除します。置換成功時に既存の `CAcpakReader` が開いていても
安全です。そのハンドルは旧スナップショットを保持し、新しい読み取り側は置換後の内容を読みます。

読み取り側と書き込み側の OS パスは UTF-16 コード単位 1,023 個までです。空パスと上限超過は、
出力先を変更する前に拒否します。

## マニフェスト上限と正準パス

既存形式の次の上限を検証付き契約に含めます。

- 項目は最大 1,048,576 件。
- 仮想パスは最大 4,096 UTF-16 コード単位。
- 所有するパスプール領域は最大 256 MiB。
- 位置とサイズの全計算は、確保または I/O の前に減算形式でオーバーフローを検証する。

正準仮想パスは空でない相対パスで、スラッシュ区切りでなければなりません。
制御文字、バックスラッシュ、コロン、空区間、`.`、`..`、埋め込み NUL、
対応しない UTF-16 サロゲートを拒否します。書き込み側と非信頼マニフェストの読み取り側は
どちらも重複する仮想パスを拒否します。

項目データは固定ヘッダーより後、マニフェストより厳密に前になければなりません。
空でないデータ範囲同士の重なりは禁止です。v1 の `padding` と `reserved` は
0 である必要があり、解析済みマニフェストは EOF で正確に終わらなければなりません。
これにより未知のスキーマ拡張を誤って v1 として解釈しません。

## トランザクション読み取り

`CAcpakReader::Open()` はまず完全な読み取り状態を準備領域に構築します。マジック値、バージョン、
フラグ、予約フィールド、件数、パスプール、項目範囲、重複、正確な EOF を検証してから
準備済み状態を反映します。確保失敗や不正入力があっても、それまで
開いていたアーカイブは引き続き利用できます。

読み取り側はマニフェスト解析の前後でファイル識別情報、サイズ、最終書き込み時刻を記録します。
変化は `kAcpakSubFileChanged` として報告します。ハンドルは読み取りと削除を共有して開き、
POSIX 置換方式により既存スナップショットを無効化せず新しいパスを公開します。

安定したマニフェストエラー補助コードは次のとおりです。

- `kAcpakSubBadPath`
- `kAcpakSubDuplicatePath`
- `kAcpakSubBadSchema`
- `kAcpakSubFileChanged`
- `kAcpakSubAtomicReplace`
- `kAcpakSubBadMagic`、`kAcpakSubBadVersion`、`kAcpakSubBadFlags`、
  `kAcpakSubBadSize`、`kAcpakSubOutOfMemory`、`kAcpakSubIOFailure`

## CAssetRegistry の検証境界

`CAssetRegistry::TryRegisterLoader()` は null のローダー、拡張子文法、重複拡張子、
終了状態、確保失敗を検証します。従来の `RegisterLoader()` は
互換ラッパーとして残します。

レジストリパスは UTF-16 コード単位 1,023 個までです。同期または非同期読み込みは同じ検証を使い、
非同期ジョブは受理した完全なパスを所有します。切り詰め前の入力から ID を作りながら
パスだけを黙って切り詰めることはありません。キャッシュ挿入も確保を検証し、
即時停止するコンテナ操作の代わりに安定したメモリ不足エラーを返します。

## テスト

`tests/assetpack_manifest_safety_tests.cpp` は次を検証します。

- 開始失敗時の状態不変。
- 埋め込み NUL、重複、上位移動、予約スキーマの拒否。
- 不正な `AddFile` 後の保留一覧不変。
- 旧読み取り側を開いたままの原子的置換。
- 確定前に中断した場合の既存アーカイブ保護。
- 検証付きローダー登録、拡張子重複、メモリ不足。
- 同期または非同期のパス上限超過を切り詰めず拒否すること。
