# JSONアセット境界の安全契約

タイルマップJSONとスプライトアトラスJSONは、信頼できない入力として
`FTilemap::TryLoadTiledJson` と `FSpritePack::TryLoadAtlasJson` から読み込みます。
従来の `LoadTiledJson` / `LoadAtlasJson` は互換ラッパーで、検査付き結果の安定した
エラー番号を `FErrorCode::subcode` へ伝えます。

## 共通JSONパーサーとの責務分担

共通の `ParseJson` は JSON 文法、Unicode エスケープ、末尾の余分なデータ、再帰深度 256 を検査します。
一方、次の制約は持ちません。

- 入力全体、文字列、ノード数の用途別上限
- オブジェクトの重複キー
- 数値オーバーフロー後の Inf
- アセットスキーマ、次元、配列長、積算サイズ
- DOM 構築中の回復可能なメモリ不足通知

各検査付きローダーは、DOM を作る前に入力バイト数、埋め込み NUL、文字列の未加工長、
深度 64 を走査します。DOM 作成後は全ノードを巡回し、ノード数、デコード後の文字列長、
重複キー、NaN / Inf を検査します。その後に用途別スキーマを全件検証し、最後に
`TryReserve` / `TryResize` / `TryAppend` だけで別の保存領域へ構築します。

共通パーサー内部の DOM 確保は現状、失敗時に即時停止します。このためローダーの事前上限は
DOM 確保量を抑える重要な防御ですが、OS レベルの極端なメモリ不足を
`TryLoad...` の戻り値へ変換するものではありません。ローダーが所有する最終保存領域の
確保失敗は `AllocationFailure` として回復可能で、既存状態を変更しません。

## FTilemap

| 項目 | 上限 |
|---|---:|
| JSON入力 | 8 MiB |
| JSON深度 | 64 |
| JSON文字列 | 4,096 バイト |
| JSON ノード | 1,100,000 |
| 幅と高さ | 各 2,048 |
| 1 レイヤーのセル | 262,144 |
| タイルレイヤー | 32 |
| 全レイヤーのセル合計 | 1,048,576 |

`width`、`height` は正の整数、`tilewidth` は正の有限数、`layers` は配列でなければ
なりません。各タイルレイヤーの `data` は必須で、要素数は厳密に `width * height` です。
不足分のゼロ埋めや余剰分の切り捨ては行いません。全 GID は有限な `u32` 整数として検証し、
タイル ID の反転ビットを除去した後、従来互換の `u16` 範囲制限を適用します。

`width * height` と `cells * layers` は除算による上限確認後だけ乗算し、整数周回と
過少確保を防ぎます。全レイヤーを別の二重 `TArray` へ構築後、失敗しないムーブだけで
反映します。失敗時は既存の次元、タイル値、容量、`LayerData` ポインターが不変です。

タイルマップ JSON は拡張メンバーを含められるため、未知メンバーと非タイルレイヤーは許可します。
既知メンバーの型違いと、オブジェクト内の重複メンバーは拒否します。

`TryInit` も同じ次元、積算、確保契約を使います。互換 `Init` は従来どおり 0 を
最小値へ補正しますが、上限超過やメモリ不足では既存マップを保持します。

## FSpritePack

| 項目 | 上限 |
|---|---:|
| JSON入力 | 4 MiB |
| JSON深度 | 64 |
| JSON文字列 | 4,096 バイト |
| JSON ノード | 100,000 |
| フレーム数 | 4,096 |
| フレーム名 | 255 バイト |
| 画像パス | 1,024 バイト |
| アトラスの幅と高さ | 各 65,535 |

ハッシュ形式と配列形式を受け付けます。`meta.image` と `meta.size.w/h` は必須です。
フレームの `x/y/w/h` は `u32` 整数、`w/h` は 1 以上でなければなりません。
`x + w` を直接計算せず、`w <= atlas_width - x` の形でアトラス内包とオーバーフローを
同時に検証します。基準点が存在する場合は `x/y` 両方を必須とし、有限な `[0,1]` だけを
許可します。

JSON オブジェクトの重複キーと、ハッシュまたは配列の両形式にある重複フレーム名を拒否します。
`rotated`、`trimmed` などの未知拡張メンバーは許可します。

画像パス、フレーム名、フレーム配列をすべて別保存領域へ構築後にムーブ反映し、最後に
内部所有の画像パスへ `m_Info.atlas_texture_path` を結び直します。失敗時はフレーム配列、
所有する名前と画像、容量、`AllFrames` / `FindFrame` / `Info` が公開済みのポインターを
含めて不変です。

両クラスはアロケーター注入コンストラクターを持ちます。アロケーターはオブジェクトより長く
生存させる必要があります。すべての永続配列と文字列は同じ注入アロケーターを使用するため、
メモリ不足テストとゲーム側の確保方針を一貫させられます。

## 診断と更新規則

検査付き結果は固定列挙値、元の JSON 解析器の補助コード、失敗したレイヤーと要素、またはフレーム
番号を返します。ログには `TilemapLoadErrorName` / `SpritePackLoadErrorName` を
使用できます。既存の列挙値は変更・再利用せず、新しい理由は末尾へ追加してください。
