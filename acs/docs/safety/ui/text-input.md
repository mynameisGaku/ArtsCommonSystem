# UI テキスト入力の編集機能と安全性

`CTextInput` は UTF-8 の1行エディタである。`FString` がバイト指向のため、
カーソルと選択基点はバイトオフセットで保持するが、公開操作の前後では必ず
デコード済みコードポイントの境界へ正規化する。

## 編集 API

- `Left` と `Right` は1バイトではなく1コードポイントずつ移動する。
- `Home` と `End` は先頭と末尾へ移動する。
- `Shift+Left` / `Shift+Right` は選択基点を固定し、カーソル側を1コードポイントずつ
  移動して選択を拡張または縮小する。基点を越えた逆方向の選択も保持できる。
- `Shift+Home` / `Shift+End` は基点を固定したままカーソルを先頭または末尾へ移動する。
- `Ctrl+A` は文字列全体を選択する。左右どちらの Ctrl も同じ扱いになる。Ctrl+Alt として
  通知される AltGr は文字入力を優先し、全選択と誤認しない。
- `Backspace` はカーソルの直前、`Delete` はカーソルの位置にあるコードポイントを削除する。
- 選択中の文字入力は選択範囲を置換し、`Backspace` と `Delete` はどちらも選択範囲全体を削除する。
- 選択中の `Left` と `Right` は、それぞれ選択範囲の先頭と末尾へカーソルを折り畳む。
- `TrySetCursorByteOffset` は範囲内かつ UTF-8 境界上のオフセットだけを受理し、成功時に選択を解除する。
- `CursorByteOffset` は正規化済みのカーソル位置を返す。

プログラムからの選択操作には次の API を使う。

- `HasSelection`
- `SelectionStart` / `SelectionEnd`
- `TrySetSelection`
- `ClearSelection`
- `SelectAll`

`TrySetSelection(start, end)` は `start <= end` かつ両端が UTF-8 境界の場合だけ成功し、
カーソルを `end` へ置く。失敗時はカーソル、基点、末尾追従状態を変更しない。
`SelectionStart` と `SelectionEnd` は基点とカーソルの向きに依存せず、小さい側と
大きい側のオフセットを返す。

`CUiInput` は `CInput::IsKeyDown` から左右の Shift / Ctrl / Alt / Super を読み取り、
`FUiKeyModifiers` の1フレーム分のスナップショットとして3引数版
`CWidget::OnKey(key, pressed, modifiers)` へ渡す。基底の3引数版は従来の2引数版へ転送するため、
既存ウィジェットが2引数版だけをオーバーライドしていてもキー配信は継続する。2引数版を直接呼ぶ
既存コードも修飾キーなしとして従来どおり動作する。`CTextInput` 派生型についても3引数版が
修飾キースナップショットを一時保持して仮想2引数版へ転送するため、2引数版だけをオーバーライドした
既存派生へ実際の `Dispatch` の押下と解放が届く。組み込み編集も残すオーバーライドは
`CTextInput::OnKey(key, pressed)` を呼ぶ。編集キーは押下で `pressed=true`、
解放で `pressed=false` を配信する。`Ctrl+A` は A の押下を受けたウィジェットの実体 ID を記録し、
Ctrl を先に離した場合でも同じ生存ウィジェットへ対応する A の解放を送る。

新規入力、末尾追従中の外部テキスト更新、ポインターフォーカスでは従来どおりカーソルが末尾に
置かれる。ポインター API からグリフの位置判定情報を得られないため、クリック位置へのカーソル配置は
まだ行わない。

## `CUiInput` の寿命保証

`CUiInput` はホバー、ポインター押下、フォーカスの対象を非所有の生ポインターでは保持しない。
各 `CWidget` の生存中アドレスを整数化した比較専用アドレストークン、構築モジュールが使った
世代カウンターのアドレスを整数化したモジュールトークン、0 を除外したモジュール内世代番号
の3要素から成る識別値だけを保存し、`Dispatch` のたびに現在生存するルート部分木を走査して
対象を解決する。アドレス・モジュールトークンはポインターへ戻さず、決して参照しない。モジュールトークンは
`CWidget` のコンストラクターが一度だけメンバーへ保存する。入力処理は
`CWidget::InputAccess().Identity()`、つまり `FInputAdapter::Identity()` を通して識別値を取得し、
呼び出し側のモジュールではモジュールトークンを再計算しない。

- ルートの複合識別値が変わった場合は、以前のルートやウィジェットを参照する前に全追跡を破棄する。
- アロケーターが以前と同じアドレスへ新しいルートまたはウィジェットを構築しても、実体 ID が異なるため
  古いホバーやフォーカスを継承しない。
- インラインカウンターが DLL ごとに独立し、同じウィジェットアドレスと世代番号を同時または逐次
  使用しても、両 DLL が読み込み中なら保存済みモジュールトークンが区別する。`u64` 周回時も予約値 0 を
  返さず、3要素の比較を維持する。
- 同じルート内で子が除去された場合も、現在の所有部分木に ID が見つからなければ
  追跡を破棄し、解放済み領域を参照しない。
- 非表示になったウィジェットとその部分木は入力対象から外し、対応する一時状態も解除する。
- `Reset()` はウィジェットを参照せず追跡 ID だけを破棄するため、ルートの破棄直前にも呼べる。
  同じ生存ルートを再び `Dispatch` すると、新規採用時に部分木の一時入力フラグを初期化する。
  `Reset(live_root)` は、生存が保証されたルートのホバー、フォーカス、押下状態も再帰的に解除する。

DLL を解放して同じベースアドレスへ再読み込みすると、モジュールトークンの元になったカウンター
アドレスとウィジェットアドレスに加えて世代番号まで再利用され得る。この境界は識別値だけで
旧実体と新実体を区別できないため、ホスト側の `CUiInput` はモジュール所有ルートがまだ生存中なら
`Reset(live_root)` を呼んでからルートを破棄し、DLL を解放する。ルートが既に破棄済みの場合も、
再読み込みまたは新しいルートの `Dispatch` より前に必ず引数なし `Reset()` を呼ぶ。ルート破棄と
モジュール解放の境界での `Reset` は必須契約である。

`Dispatch(root)` の呼び出し中だけは、呼び出し側が `root` 自身の寿命を保証しなければならない。
コールバックから現在の子または別の子を除去してよい。ポインター移動・押下・解放、テキスト、
キーの各配信後は保存ポインターを使わず、必要な対象を複合識別値から解決し直す。ただし
実行中の `Dispatch` が戻る前にルート自身を破棄してはならない。

複合識別値とコールバック寿命ガードは内部実装であり、保存・通信に使う永続ハンドルでも
安定したプラグイン ABI でもない。`CWidget` と `CUiInput` のレイアウトも変更されているため、
旧 DLL・プラグインと新 DLL・プラグインの混在は未サポートである。この変更を取り込むときはエンジン、
ゲームモジュール、プラグインを同じリビジョンから完全に再ビルドする。

## 通知中の子ウィジェット破棄

`TObservable::Notify` は追加確保を伴わないスタック上のガードを登録する。リスナーが `TObservable` を
所有オブジェクトごと同期破棄した場合、デストラクターが実行中のガードを失効させ、復帰した `Notify` は
破棄済みメンバーに触れず直ちに終了する。残りのリスナーは呼ばれない。
ただし MVVM コールバック側は所有者の破棄を最後の操作にし、破棄後は `new_value`、`user`、
所有者を再参照せず直ちに復帰しなければならない。

`CButton` の `clicked` パルスと `CTextInput` の編集確定・互換 `OnKey` 橋渡しもウィジェットの
スタック上の寿命ガードを使う。購読者または派生コールバックが現在の子を親ツリーから
除去した場合、破棄後に `clicked=false`、選択状態の正規化、修飾キースナップショット復元のため
`this` へ再接触しない。これらは UI スレッド上の同期コールバックを対象とする。

## 非表示ルートの描画

`CUiRenderer::Render` は `root.visible == false` のとき、ルートの `Layout`、
`CSpriteBatch::Begin/End`、ルートと子の `Render` をすべて省略する。可視性の判定処理は
GPU を使わないテストと共通化され、非表示ルートのレイアウトコールバックと描画コールバックがどちらも
呼ばれないことを検証する。

## 入力検証と上限

入力経路は C0/C1 制御文字、`DEL`、UTF-16 サロゲート、`U+10FFFF` を超える値、
Unicode の行区切り文字と段落区切り文字を拒否する。プラットフォーム由来の
UTF-8 も共通の正規デコーダーを通し、過長符号化、サロゲート、範囲外スカラー値、
不正な先頭・継続バイトをウィジェットへ渡さない。正規に符号化された `U+FFFD` は
通常文字として受理する。

入力配信側は `TryDecodeUtf8` の成否で、正規の `U+FFFD` と不正入力の診断値を区別する。
互換 API の `DecodeUtf8` も残している。どちらも不正入力では少なくとも先頭バイトを消費し、
NUL 終端を越えて読まない。

既定上限 `kDefaultMaxTextBytes` は 4096 バイト、設定可能な絶対上限
`kHardMaxTextBytes` は 1 MiB である。`TrySetMaxTextBytes` で上限を変更できる。
選択置換では「元の長さ - 選択長 + 挿入文字長」が上限以内の場合だけ成功し、
コードポイントを途中まで受け入れることはない。上限を既存値より小さくしても文字列を
暗黙に切り詰めず、削除は引き続き利用できる。

## 外部バインディングと正規化

MVVM バインディングはエディター API を経由せず `text` を置き換えられる。編集、カーソル・選択状態の
照会、描画の前に次を行う。

- 末尾追従中の端点は新しい末尾へ追従する。
- それ以外の端点は、現在長以下で最も近い直前のコードポイント境界へ丸める。
- カーソルと基点が同じ位置へ折り畳まれた場合は末尾追従状態も同期し、後続の文字列
  伸長で古い選択が復活しないようにする。
- 外部から不正 UTF-8 が渡された場合は1バイトずつ安全に進み、範囲外読みや停止を避ける。

## 確保失敗時の契約

挿入、選択置換、削除は、現在の文字列と同じアロケーターを使う一時 `FString` 上で結果を
完成させる。容量予約と追加がすべて成功した後だけ監視対象値へ移す。
無効なスカラー値、境界違反、上限超過、確保失敗では、次の状態をすべて維持する。

- 以前の文字列バイト列
- カーソル位置
- 選択基点の位置
- 各端点の末尾追従状態
- 監視対象値の通知回数（失敗時は通知しない）

外部バインディング後の端点正規化も編集成功まではローカルな一時状態に置かれるため、編集失敗を
内部状態へ部分的に反映しない。

## 描画と現在の範囲

キャレットと選択範囲の強調表示は `CUiRenderer::MeasureTextBytes` で UTF-8 接頭部分だけを
測り、NUL 終端の一時文字列を確保せずに位置を決める。強調表示は文字より先に
`input_selection` 色で描画し、入力欄の左右内側へ収める。

現在はクリップボード操作、IME 変換範囲、ポインターによるグリフ位置判定、文字とキャレットの
横スクロール、文字の切り抜き表示を提供しない。

テストではマルチバイト選択・置換・削除、Shift による順方向・逆方向の選択と折り畳み、
`Ctrl+A`、従来の `OnKey` オーバーライドへの互換転送、カーソル移動、外部バインディングによる短縮、境界違反、
上限超過、強制 OOM、失敗時の通知抑止を検証する。選択ハイライトの純粋な矩形計算も、
通常範囲、左右のはみ出し、長い選択、幅・高さ不足について GPU なしで検証する。
さらに実際の `CInput` 入力から押下・解放と左右修飾キーを `Dispatch` し、ルートの同一アドレス
再構築および同一ルート内のフォーカス中の子を除去した後にも古い入力状態を再利用しないことを検証する。
全入力コールバック中の現在または別の子の除去、`TObservable` 通知中の現在のウィジェット破棄、
挿入と消去の確定中における現在または別の子の除去、入れ子になった 3→2 引数の `OnKey` 後の外側の修飾キー
スナップショット復元、引数なし `Reset` 後の再初期化、非表示ルートのレイアウト・描画抑止も
GPU なしで検証する。
