# FNetSnapshot の安全境界

`FNetSnapshot` は信頼できない通信相手と、差し替え可能な `INetTransport` の両方を境界として扱う。
この文書では、バイナリ符号化、UDP トランスポート、スナップショット管理の検証順序と失敗時保証を定義する。

## 固定上限

| 対象 | 上限 |
|---|---:|
| スナップショットのデータ本体 | 4 MiB |
| リングバッファー | 4,096 スナップショット |
| 1 スナップショットのエンティティレコード | 65,536 |
| 1ティックの受信数 | 8,192メッセージ |
| IPv4 UDP データグラム | 65,507 バイト |
| スナップショット周波数の設定値 | 1〜1,000 Hz |
| 補間遅延 | 0〜60 秒 |

`TryInit` は範囲外設定を `kSub_InvalidConfig` で拒否し、以前のセッション状態を維持する。
互換 API の `Init` は、古い呼び出し箇所を壊さないため範囲内へ正規化してから `TryInit` を呼ぶ。
特にリング件数とデータ本体長を先に制限するため、設定値の乗算や巨大確保を受信処理まで持ち込まない。

## バイナリ符号化

フレームは次の完全一致形式である。

```text
[ACSN:4][version:4][tick:4][sequence:4][timestamp_us:8]
[payload_size:4][reserved_crc32:4][payload:N][crc32_footer:4]
```

- 整数はリトルエンディアン固定。
- `sequence == 0` は予約値であり拒否する。
- ヘッダー内の `reserved_crc32` は常に 0。CRC 値は末尾だけに置く。
- `payload_size + 36` は入力バッファー長と完全一致しなければならない。末尾の余分なバイトも拒否する。
- 符号化時のデータ本体と出力フレーム、復号時の入力フレームと既存出力領域は重複不可。
  再確保で入力ポインターを無効化する同一領域内の復号や、ヘッダー書き込みでデータ本体を上書きする別名参照を拒否する。
- データ本体上限の検証後にだけ CRC を計算する。
- CRC 対象はマジック値を除くバージョンからデータ本体末尾まで。
- `EncodeSnapshot` は全引数と容量を確認してから書き始めるため、失敗時にフレームを部分書き込みしない。
- `DecodeSnapshot` はマジック値、バージョン、正規ヘッダー、完全サイズ、CRC、確保の順に検証する。
  `out_header` と `out_payload` は最後の確保まで成功した場合だけ置換される。

## エンティティデータ

管理機能がリングへ入れるデータ本体は、次のレコードを末尾まで事前検証する。

```text
[entity_id:u32][component_mask:u32][data_size:u32][data:data_size]
```

`entity_id == 0`、レコードヘッダーの切り詰め、`data_size` の加算オーバーフロー、データ本体末尾を越えるデータ、
レコード途中の余分な末尾バイト、エンティティ件数上限超過は `kSub_BadEntityPayload` 相当として棄却する。
事前検証完了前にリングスロット、先頭位置、件数、最終ティックを変更しない。
`TryGetInterpolatedSnapshot` も出力配列へ参照範囲を書く前に同じ完全検証を行う。

## 検査付き API と互換 API

| 検査付き API | 成功時 | 失敗時 |
|---|---|---|
| `TryInit` | セッションを一括置換 | 既存セッション不変 |
| `TryAddEntitySnapshot` | 保留領域へ 1 レコード追加 | 保留領域と合計サイズ不変 |
| `TryCommitSnapshot` | 送信、連番と統計の更新、保留領域の消費 | 保留領域、連番、リング、統計が不変 |
| `TryTick` | 検証済みメッセージごとにリングへ反映 | 問題のあるメッセージではリング不変、詳細件数を返す |

既存の `AddEntitySnapshot`、`CommitSnapshot`、`Tick` は検査付き API を呼ぶ。
`CommitSnapshot` だけは従来の可能な範囲で処理する契約を維持し、失敗したティックの保留データを破棄する。
再送が必要な呼び出し側は `TryCommitSnapshot` を使う。

`TryTick` は複数メッセージを消費するため、途中停止より前に反映済みのスナップショットは保持する。
戻り値の `received_messages`、`accepted_snapshots`、`rejected_messages`、`received_bytes` と
`stop_subcode`、`last_rejected_subcode` で部分進行を判定できる。`stop_subcode == 0` は正常に
受信なしへ到達した状態であり、棄却フレームの最後の理由は処理継続時でも失われない。

## トランスポート契約

`INetTransport::Receive(out, capacity)` は、成功時に `0..capacity` の値だけを返さなければならない。
`capacity` より大きい値を返す実装は `kSub_TransportContractViolation` として停止し、
返された値をバッファー長として使用しない。これにより、壊れた模擬実装、プラグイン、ストリームアダプターが
復号器へ範囲外の参照範囲を渡すことを防ぐ。

`FUdpTransport` は追加で次を保証する。

- `sendto` 前に IPv4 UDP データ本体上限を検証する。
- 戻り値が要求長と異なる場合は部分データグラム成功として扱わない。
- OS へ渡す受信長を 65,507 バイト以下へ制限してから Winsock の `int` へ縮小変換する。
- `WSAEMSGSIZE` は一般受信失敗と区別し、`kSub_DatagramTruncated`で報告する。
- 切り詰められたデータグラムはスナップショット復号器へ渡さない。

## 診断カウンター

パケット数、バイト数、棄却数、トランスポート契約違反数は周回せず `u32` 最大値で飽和する。
長寿命サーバーでカウンターの周回が正常値に見えることを防ぐ。
`RejectedPackets()` と `TransportContractViolations()` は運用監視および壊れたトランスポートの特定に使う。

## テスト方針

`tests/net_snapshot_safety_tests.cpp` は次を固定する。

- 切り詰め、余分な末尾バイト、CRC 改変、非正規ヘッダーの拒否と出力不変
- データ本体の製品上限と符号化先への非部分書き込み
- 確保失敗時のヘッダーとデータ本体の不変
- 入出力保存領域の別名参照の拒否
- 不正設定で既存セッションを置換しないこと
- 送信失敗後に検査付き反映を同じ連番と保留データで再試行できること
- 正常フレーム、破損フレーム、容量超過を返す悪性トランスポートを同一ティックで処理してもリングが汚染されないこと
