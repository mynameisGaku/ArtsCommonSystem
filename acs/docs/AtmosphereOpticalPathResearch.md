# 大気の有限光路積分：導出と実CPU／GPUのTDD（2026-09-08）

## 現在地

ミー係数の経路間不一致を修正しても、固定幅の中点則が濃い地表付近を取りこぼす問題は残る。
係数と積分誤差を混同しない。[媒質整合の記録](AtmosphereMediumConsistency.md)に、
係数の実GPU試験と、修正後モデルの鉛直光路における積分則の誤差を記録した。
前半は実装前に固定した根拠と受入条件、後半は密度座標による積分を実装した検証記録である。
以下の測定値・ハッシュは当時の固定スナップショットに限る。
2026-09-12の視線監査で、共有する指数密度列にも成分別の相対誤差が見つかったため、
端点の二次変換と既知一次成分の解析積分を追加している。
更新候補の式・反例・未合格事項は[視線単散乱の検証記録](AtmosphereViewIntegralResearch.md)を参照する。
一般位置の有限地表判定は後続の[有限地表可視性](AtmosphereFiniteGroundVisibility.md)で検証した。
製品全体の精度保証ではなく、CPUとCSkyの太陽光路を改善する小単位として扱う。

## 先に固定する期待値

密度高さH、始点高度h、長さLを同じ長さ単位で与えた鉛直上向き光路は、球面でも次が厳密に成立する。

```text
C_H = H exp(-h/H) (1 - exp(-L/H))
```

C_Hは地表密度で規格化した密度の積分長であり、透過率ではない。
短区間は`-expm1(-L/H)`を使う独立参照で桁落ちを避ける。
N点の等間隔中点則との比は`q / sinh(q)`、`q=L/(2NH)`となる。
これは有限等比級数の和から導け、Hが小さい媒質ほど長区間の標本不足が大きくなる。

次の受入条件を先に試験へ置く。

- 鉛直上下の解析解、経路反転、区間の加法性。
- 長さゼロ、微小光路の`C_H/L → exp(-h/H)`、有限値。
- 地表からの水平・浅い上向き、高高度から接線をまたぐ光路。接線を中心とする対称区間の積分は片側の2倍。
- 地表に遮られる光路と、地表に触れず通過する光路。大気外からは有効区間だけを切り出す。
- オゾンの10／25／40kmの折れ目、鉛直全層の積分15km、m／km変換。
- 成分別の密度積分だけでなく、RGBの光学的厚さ・透過率の絶対誤差と実GPUコスト。

## 一次資料を精査して分かった注意点

主担当と独立調査担当が[Yue 2024の本文](https://acp.copernicus.org/articles/24/5093/2024/)を確認した。
式(9)は距離を半径変化へ変換し、式(10)で薄い大気の近似を導入する。
一定の密度高さ、球対称の指数密度、直線光路が前提で、現実の全ての大気を保証する式ではない。
記載された誤差評価を、任意の有限区間・HLSL単精度の保証へ広げない。

式(5)の積分Iと規格化されたCdの関係へ戻ると、接線で分けた式(15)の右辺は接点基準であり、
元の始点基準のCdとして使うなら`exp((D-b)/H)`の換算が必要になる。Dは元の半径、bは接点半径。
この注意は定義からの独立導出であり、著者からの訂正確認を得たものではない。
実装では各区間を物理的な密度積分長へ戻してから足し、正規化の違う値を直接足さない。

[著者検証コード](https://raw.githubusercontent.com/ydx2021/yuedx/main/ydx_chapman_eval.py)にも、
次の反例を主担当が確認した。コードの式をメモリ内で評価した結果であり、ACS実行結果ではない。

| 条件 | コードの結果 | 独立した期待値 |
| --- | ---: | ---: |
| `y1=0, y2=1e-8, z=0, lambda=795`、既定の分岐条件 | 約1.000628931 | 鉛直Cdは約0.000007949968399 |
| `y1=y2=0.01, z=0, lambda=100` | 約−0.1360058674 | ゼロ幅の積分なので0 |

前者は長区間極限への分岐で、区間が十分長い条件を確認していない。
後者は下端項で乗算でなく累乗を使うため、上下端の相殺が成立しない。
元コードを製品へコピーせず、近似式の条件・単位・極限から検証する。

## 比較候補：最低高度で分割し、密度変化を積分座標へ使う

独立調査担当が提案し、主担当も変数変換を代入して確認した候補。
既報の精度保証はない。以下は実装前の候補であり、単精度・有限区間・GPU負荷を後半で検証する。

光路内に最接近点があればそこで分け、各区間を低高度端から高高度端へ向ける。
低高度端の半径をr_a、惑星半径をR、直線と惑星中心の最短距離をb、
`a=sqrt(r_a²-b²)`、各点の半径をrとする。

```text
w = 1 - exp(-(r-r_a)/H)
u = sqrt(a² + 2 r_a H w) - a
delta = -log(1 - u(u+2a)/(2 r_a H))

C_H = exp(-(r_a-R)/H) * integral[0,u_b] G(u) du
G(u) = (a+u)(r_a+H delta) / (r_a sqrt(a²+H delta(2r_a+H delta)))
```

半径での積分は`exp(-(r_a-R)/H) * H * r/sqrt(r²-b²) dw`となるため、上の変換を導ける。
鉛直ならb=0、a=r_aとなり、Gは`1+u/r_a`に簡約する。接線a=0でもu→0の極限は1で有限。
これにより、指数密度を見落とさず、接線で生じる見かけの特異点を取り除く可能性がある。

実装前に次の問題を受入条件へ入れた。

- 小さいwでの平方根同士の差、`log(1-w)`、高度の差の桁落ち。式を安定な形へ変形する。
- wが1へ丸まる長区間と、非常に薄い高高度の密度。相対誤差だけを目的にしない。
- 成分別の変換で増える対数・平方根のコスト。現在は同じ標本位置で複数成分を評価している。
- オゾンは指数密度ではないので、ミー用の標本・重みをそのまま全消散へ流用しない。
- 通常C++、GPU大気表、Skyが同じ積分契約を共有する方法と、既存公開APIとの互換性。

比較する数値参照は、鉛直解析解と、球面の直接光路を倍精度で別途積分した値を使う。
候補自身の変数変換を参照側にも使って、同じ誤りを相殺しない。

## 試験基盤にも残る注意

独立監査で共通`EXPECT_NEAR`はNaNを見逃すだけでなく、差をf32へ狭めることも確認された。
例としてdoubleの`1+2^-25`と0を許容差1で比較すると、差の丸めで誤合格になり得る。
今回の空試験には有限値検査を追加済みだが、共通マクロ全体を直したわけではない。
新しい積分試験ではこれを前提にせず、有限値と倍精度の誤差を明示して判定する。
共通マクロの修正は、期待した失敗を実際に捕捉する自己試験を先に用意する別の小単位とする。

## 実装範囲と数値上の対策

`Sky.cpp`の`PhysicalTransmittance`と、`Atmosphere.cpp`の太陽光路3呼出しを変更した。
CPUの視線側`Transmittance`、単散乱の視線区間、GPU大気表の積分は変更していない。
公開型・関数の宣言と配置は維持する。CPUの`sun_steps`は一方向に高度が変化する区間ごとの
各指数密度の評価数として使い、0は既存の呼出し元で1へ補正する。
CPUは1／2／4／8点のGauss則を組み合わせ、20点なら8＋8＋4、24点なら8＋8＋8となる。
GPUは各指数密度に8点を使う。オゾンは両経路とも密度の折れ目で分けた2点則であり、
曲がった高度変化を含むと厳密解ではない。

- `a`は半径二乗の差の平方根ではなく、最低高度点と方向の射影から求める。
- 最低高度が光路内にあるときだけ二分し、地中の仮想接点から巨大な密度を持ち上げない。
- 半径増加と変換座標上端は平方根同士を引かず、二乗差を分母で割る。
- CPUは倍精度の`expm1`／`log1p`、GPUは短区間の指数減衰差と対数の級数を使う。
  対数では`q=w/(2-w)`へ変換し、`w<=1/8`なら`|q|<=1/15`となる範囲で奇数級数を評価する。
- Gauss標本は区間端を含まないため、上端のwが1へ丸まっても`log(0)`を直接評価しない。
- 密度変化が0へ丸まる場合は局所密度一定の極限、標本の距離が0へ丸まる接線極限は倍率1を使う。
- 方向を正規化したときは距離も方向長で補正し、光路端を変えない。
- m／kmと係数の逆単位を対応させ、前回確定した散乱・消散係数は調整しない。

独立監査で、オゾンの光路端を`height+rise`から再生成する初版に反例が見つかった。
高度25km・水平110mでは高度差が丸まって区間が消え、110.4mでは区間が約156mへ伸びる。
実GPUでも緑の透過率0.999934435に対して独立参照0.999727600となり、2e-4の基準を破った。
修正後は密度帯との交点距離だけを計算し、必ず元の`[0,distance]`に収める。
密度も大きい高度同士の差でなく、密度帯の端からの差で評価する。
同じ110m条件の実GPU値は0.999727547となった。

反転試験では既存の地表交点にも、鉛直1mの終点をわずかに越境と判定する丸めが見つかった。
北極に相当する座標からの鉛直地表交点は二次方程式でなく厳密な一次式で求める。
一律の距離補正や地表の持上げは加えていない。一般方向のCPU遮蔽との差は残る。

## 負荷診断と未合格の範囲

同じ計算シェーダーの実行時分岐で、旧8点中点則と現積分を交互に比較した。
各画素の高度0〜40kmと太陽方向を変え、640×360の230400光路を評価する。
各方式2回の慣らし後12回ずつ計測し、コンパイルと読戻しは除外した。
計測量はCPU時計での`Submit`から`WaitIdle`までであり、GPUタイムスタンプでも空全画面の時間でもない。

RTX 4070 SUPER／Raw DX12、`ozone-short-green-debug.log`では、旧平均0.065908ms／現平均0.073750ms、
旧最短0.063300ms／現最短0.069000msだった。この測定では負荷が増えており、最適化完了とはしない。
1光路ずつの診断を、視線16区間を持つ空の描画時間へそのまま外挿しない。

残る課題は、成分別の積分誤差・全入力範囲、GPU大気表との統合、視線側の収束、
CPUの地表境界、太陽円盤の照度／輝度・透過・遮蔽、地上／上空／雲内の連続画像、
実解像度負荷、配布物と外部Frameworkの再導入である。商用品質は未合格を維持する。

Editorの到達性も別担当が静的に追跡し、主担当が描画分岐を照合した。
通常の直接描画は修正済みの`CSky`を使うが、CSky初期化失敗時の`kSky3DHLSL`には旧物理空が残る。
この複製は16点中点則、ミー散乱の二重加算、旧地表式を含み、今回の修正を共有していない。
Editor ABIのビルド成功を、この例外経路まで統一された証拠にしない。
太陽円盤もEditor／通常C++のIBL経路で換算が異なり、シーンの最初のHDR格納は既定RGBA16F、
露出適用はその後である。経路統合と格納範囲の受入れを別途必要とする。
### 追加監査で判明した次の優先課題

積分変更の再監査で、既存の一般位置の地表交点式に別の丸めの反例が見つかった。
`origin=(1000,0.000001,0)km`、`direction=(-1,0,0)`、`distance=2000km`は地表1mm上を通るが、
判別式の真値約−0.01272が単精度で0へ丸まり、地表に遮られると判定する。
独立した球面参照では赤の透過率は約0.0114273。現在は単精度模擬での反例であり、実GPUの再現前である。
北極以外の係数生成も補償演算へ拡張するTDDを次の最優先とし、±1mmの通過／遮蔽と反転を確認する。
これは新積分の係数調整で回避せず、交点式そのものの別の小単位として扱う。
その後、太陽円盤の加算・透過・地表遮蔽を、公開描画の失敗試験から修正する。
