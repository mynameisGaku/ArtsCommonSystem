FInputRecordingView

caller-owned の .acsr バイト列を全検証し、sample 領域を中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。せず借用する immutable decoder。 header、製品上限、厳密サイズ、データから計算する 32bit のチェック値。 破損や改竄の検出に使う。、mouse の有限値を allocation 前に検査する。

クラス
対応するAPI: acs::game::FInputRecordingView

使う場面

mapped file や受信バッファを所有配列へ展開せず、安全に順次参照したい時。 記録を長期保持・編集する場合は Cキーボード・マウス・ゲームパッドの状態を問い合わせで読む静的クラス。 毎フレーム先頭で Update() を呼んでから状態を読む。Recorder::TryLoadFromBuffer を使う。

API項目 1

static TResult<FInputRecordingView> Decode(TSpan<const u8> bytes)
説明
magic/version、tick rate・件数上限、厳密サイズ、データから計算する 32bit のチェック値。 破損や改竄の検出に使う。、全 sample の有限 mouse 値を検査する。 null、truncation、破損、上限超過は失敗し、キーボード・マウス・ゲームパッドからの操作。 ACS では CInput でその瞬間の状態を読む。を所有しない。
戻り値
検証済み view または ACS の標準エラー型。 カテゴリ・サブコード・OS エラー値・メッセージ・発生位置をまとめて持つ POD。

使用例

TSpan<const u8> bytes(fileData, fileSize); // view より長く生存し、不変に保つ
TResult<FInputRecordingView> result = FInputRecordingView::Decode(bytes);
if (result.IsOk()) {
    FInputSample sample;
    result.Value().DecodeSample(0u, sample);
}
