CReplayDirector

高レベルなプレイの入力や状態を記録し、後で同じ進行を再生する仕組み。 決定論的な乱数と相性が良い。制御。 録画開始/停止・再生・一時停止・倍速・任意位置への再生位置を任意の時点へ飛ばすこと (スクラブバー操作など)。を、ゲーム UI の粒度で扱う。 低レベルのキーボード・マウス・ゲームパッドからの操作。 ACS では CInput でその瞬間の状態を読む。記録 (Cキーボード・マウス・ゲームパッドの状態を問い合わせで読む静的クラス。 毎フレーム先頭で Update() を呼んでから状態を読む。Recorder) と全プレイヤーが同じ入力フレームを共有して同期する決定論シミュレーション方式。 (CLockstep) をまとめる。

クラス
対応するAPI: acs::game::CReplayDirector

使う場面

プレイのプレイの入力や状態を記録し、後で同じ進行を再生する仕組み。 決定論的な乱数と相性が良い。を残したい、ベストプレイを後で再生したい、バグ再現用に録画したい時。

API項目

API項目 1

void Init()
説明
状態機械の「何もしていない/開始前」を表す既定状態。 Idle→Walk のように、ここから他状態へ遷移する。 オブジェクトが取りうる局面を区別した値(例: Idle / Spawning)。 状態機械の各点。にリセットする。 再生速度 1.0・tick 0。
対応API
acs::game::CReplayDirector::Init メンバー関数

API項目 2

void SetSources(CInputRecorder* recorder, CLockstep* lockstep)
説明
保存/復元の対象となる低レベル source を注入する (そのポインタ/参照は対象を所有しておらず、寿命管理 (解放) は別の誰かが行うこと。 non-owning。)。
対応API
acs::game::CReplayDirector::SetSources メンバー関数

API項目 3

TResult<void> StartRecording(const FReplayMetadata& meta)
説明
録画を開始し、メタデータを中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。保存する。 状態機械の「何もしていない/開始前」を表す既定状態。 Idle→Walk のように、ここから他状態へ遷移する。 以外で呼ぶと kSub_BadMode。
対応API
acs::game::CReplayDirector::StartRecording メンバー関数
対応API
acs::game::FReplayMetadata 構造体

API項目 8

void SeekToTick(u32 tick)
説明
再生位置を任意の tick に飛ばす。 末尾を超えたら末尾に値を指定範囲内に収めること。 Saturate は 0〜1 に収める。。
使う場面

対応API
acs::game::CReplayDirector::SeekToTick メンバー関数

API項目 9

void Tick(f32 dt)
説明
毎ゲームループの 1 回分の更新＋描画。 1 秒に何フレーム回るかが FPS。呼ぶ。 録画中は tick を進め、再生中は速度倍で進める。
対応API
acs::game::CReplayDirector::Tick メンバー関数
