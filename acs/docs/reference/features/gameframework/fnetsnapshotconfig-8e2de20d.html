FNetSnapshotConfig

CNetSnapshot のランタイム設定。 commit 目標 Hz・ring buffer 件数・2 つの値 (ここでは前後の snapshot) の間を滑らかにつないで中間の状態を作ること。 少し過去の時刻を狙うことで通信ジッタを吸収する。必要になるまで計算を先延ばしにする方式(lazy)。 現行 TDerived は生成時と依存通知時に即時評価し、Get の再計算は dirty が残った場合の補完経路。秒・ImGui のドラッグ & ドロップで運ばれるデータ本体。 ACS の CAssetBrowser では "ASSET_PATH" id で wchar_t* を渡す。 上限。

構造体
対応するAPI: acs::game::FNetSnapshotConfig

使う場面

Init に渡す。

API項目

API項目 1

u32 snapshot_rate_hz
説明
server の目標 commit Hz (自動 throttle はしない)。
対応API
acs::game::FNetSnapshotConfig::snapshot_rate_hz メンバー変数

API項目 2

u32 buffer_capacity_snapshots
説明
client 側 ring buffer 件数 (>=2 必須)。
対応API
acs::game::FNetSnapshotConfig::buffer_capacity_snapshots メンバー変数

API項目 3

f32 interpolation_delay_sec
説明
2 つの値 (ここでは前後の snapshot) の間を滑らかにつないで中間の状態を作ること。 少し過去の時刻を狙うことで通信ジッタを吸収する。の必要になるまで計算を先延ばしにする方式(lazy)。 現行 TDerived は生成時と依存通知時に即時評価し、Get の再計算は dirty が残った場合の補完経路。 (= jitter buffer の深さ)。
対応API
acs::game::FNetSnapshotConfig::interpolation_delay_sec メンバー変数

API項目 4

u32 max_payload_bytes
説明
1 ある時刻の世界全体の状態を 1 つに固めたもの。 server がこれを配信し、client は受信した複数 snapshot を補間して表示する (FPS/MMO 系で標準)。 の ImGui のドラッグ & ドロップで運ばれるデータ本体。 ACS の CAssetBrowser では "ASSET_PATH" id で wchar_t* を渡す。 上限。
対応API
acs::game::FNetSnapshotConfig::max_payload_bytes メンバー変数
