CHotReloadWatcher

Windows 開発ビルドで ReadDirectoryChangesW を処理の完了を待たずに先へ進み、結果は後で受け取るやり方。 重い読み込みなどで画面を止めない。駆動し、変更を bounded FIFO と安定 ある時刻の世界全体の状態を 1 つに固めたもの。 server がこれを配信し、client は受信した複数 snapshot を補間して表示する (FPS/MMO 系で標準)。 のあとで呼んでもらうために登録しておく関数。 ACS では関数ポインタ + void* ユーザーデータの形を取る(STL 不依存方針)。へ配る single-thread-affine watcher/queue 差し替え可能な境界面。 実装(backend)を後から入れ替えられるよう、インターフェースだけを切り出した接合点。。 path は UTF-8 の所有中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。で、同一 path の burst を debounce できる。 ゲームで使う画像・音・モデル・データなどの素材ファイル。再 import や 型ごとにイベントを同期配信するpub/subバス。 1 スレッド内で使う。 publish は上位利用側の責務。

使用例

CHotReloadWatcher w;
w.Init();
if (w.TryWatchDirectory("Assets/Textures", true) != EHotReloadResult::Success) return;
w.TrySetDebounceSeconds(0.05f);
w.TryRegisterCallback(&OnReload, this);
// 毎フレーム:
w.TryTick(dt);
const FHotReloadDiagnostics d = w.CaptureDiagnostics();
if (d.authoritative_rescan_required) {
    RescanAssets();
    w.ClearDiagnostics();
}
