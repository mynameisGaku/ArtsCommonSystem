ACS 機能 / gameframework

TPool<T>

短命オブジェクトを毎ゲームループの 1 回分の更新＋描画。 1 秒に何フレーム回るかが FPS。大量に作っては捨てる用途のオブジェクトを毎回 new/delete せず、あらかじめ確保した固定数を使い回す手法。 確保コストと断片化を抑える。。 固定容量で、要素 T は最初に全部 default 構築しておき、m_Active[i] の 0/1 で使用中かを表すだけ。 new/delete を避けてメモリ確保 / 解放やガベージコレクションが原因で一瞬だけフレームが詰まること。 プールはこれを避けるために使う。や断片化を防ぐ。

クラステンプレート
対応するAPI: acs::game::TPool

使う場面

弾・炎・煙・火花などを表現する大量の小さな粒子。 1 つ 1 つが位置・速度・寿命を持って動く。・一時的な敵など、生成と破棄が高頻度なものを軽く取り回したい時。 Acquire / Release では T のコンストラクタ / オブジェクトが破棄される時に自動で呼ばれる後始末の関数(~ClassName)。は走らないので、再初期化は自分で行う。

API項目

API項目 1

void Init(u32 capacity)
説明
固定容量を予約 (T は default 構築される)。 2 度目以降は 何もしない処理。 呼んでも安全で副作用が無いこと。 (固定容量ポリシー)。
対応API
acs::game::TPool::Init メンバー関数

API項目 2

T* Acquire()
説明
空き 1 個を確保して返す。 満杯なら nullptr。 中身は前回値が残るので再初期化すること。 返ったメモリ上の場所(アドレス)を指す値。 中身そのものではなく『在りか』を持つ。は ResetAll / 破棄まで安定。
戻り値
空きスロット または nullptr
対応API
acs::game::TPool::Acquire メンバー関数

API項目 3

void Release(T* p)
説明
p をあらかじめ確保した固定数の枠を使い回す仕組み。 確保/解放のコストとフレーム落ちを避けられる。に返す。 nullptr / 範囲外メモリ上の場所(アドレス)を指す値。 中身そのものではなく『在りか』を持つ。 / 二重 Release は 何もしない処理。 呼んでも安全で副作用が無いこと。 (安全)。
対応API
acs::game::TPool::Release メンバー関数

API項目 4

void ResetAll()
説明
全 active を一括解放 (中身の T は触らない)。
対応API
acs::game::TPool::ResetAll メンバー関数

API項目 5

void ForEachActive(F&& fn)
説明
active な要素だけ fn(T&) で巡回。 update / draw 用。 fn 内での Acquire/Release はC++ 規格が結果を保証しない操作(配列外アクセス・寿命切れポインタ等)。 最適化で表面化しやすい。。
対応API
acs::game::TPool::ForEachActive メンバー関数

API項目 6

u32 ActiveCount() const
説明
使用中の数。 Capacity() は容量。
対応API
acs::game::TPool::ActiveCount メンバー関数

使用例

struct FBullet { f32 x, y, vx, vy; bool alive; };
TPool<FBullet> bullets;
bullets.Init(1024);
if (FBullet* b = bullets.Acquire()) {
    b->x = px; b->y = py; b->vx = vx; b->alive = true;
}
bullets.ForEachActive([dt](FBullet& b) {
    b.x += b.vx * dt;
});
