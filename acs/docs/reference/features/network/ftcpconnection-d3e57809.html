FTcpConnection

確立済みの 相手と接続を張り、順序どおり・確実にデータを届ける通信方式。 取りこぼしが許されない用途向け。 関連語 UDP。 接続 1 本。 順序どおり・確実にデータを送受信できる。 クライアントとして自分から繋ぐか、サーバの FTCP 接続を待ち受ける側(サーバ)。 Accept() でクライアントの接続を 1 本ずつ受理して TcpConnection にする。 が受理した接続として得る。 中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。不可・中身をコピーせず所有権ごと移すこと。 大きなデータを安く引き渡せる。のみで、オブジェクトが破棄される時に自動で呼ばれる後始末の関数(~ClassName)。で自動的に切断する。

クラス
対応するAPI: acs::FTcpConnection

使う場面

相手と確実にデータをやり取りしたい時(チャット・ログイン・オブジェクトが取りうる局面を区別した値(例: Idle / Spawning)。 状態機械の各点。処理が終わるまでその場で待つやり方。 結果がすぐ手に入る代わりに止まる。など、取りこぼしが許されない通信)。

isize Send(const void* data, usize size)
説明
バッファを送信する。 部分送信あり。 size>0 で null、Windows のソケット通信ライブラリ。 ACS の CNetwork はこれを薄くくるんでいる。 上限超過、失敗時は -1。 size=0 は領域を参照せず 0。

API項目 3

isize Recv(void* buf, usize size)
説明
データを受け取る。 size>0 で null、Windows のソケット通信ライブラリ。 ACS の CNetwork はこれを薄くくるんでいる。 上限超過、失敗時は -1。 size>0 で 0 なら相手が切断、size=0 は OS を呼ばず 0。
戻り値
受信バイト数
使用例
isize n = c.Recv(buf, sizeof(buf));
if (n == 0) { /* 相手が閉じた */ }

API項目 8

説明
内部用。 FTCP 接続を待ち受ける側(サーバ)。 Accept() でクライアントの接続を 1 本ずつ受理して TcpConnection にする。::Accept が受理したネットワーク通信の出入口となる OS の口。 ここを通じてデータを送受信する。から接続を組み立てる。 通常は直接使わない。
