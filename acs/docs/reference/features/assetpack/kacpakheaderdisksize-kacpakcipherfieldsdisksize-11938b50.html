kAcpakHeaderDiskSize / kAcpakCipherFieldsDiskSize

.ACS のアセットアーカイブ形式(.acpak)。 出荷時に複数ファイルを 1 つにまとめる。 のディスク上の固定バイト数。 kAcpakHeaderDiskSize = 36 はヘッダ実体長(sizeof(FAcpakHeader) は構造体パディングで 40 になり得るため I/O はこの値で明示)。 kAcpakCipherFieldsDiskSize = 28 は鍵を知らないと中身を読めない形にデータを変換すること。ON/OFF を表す印。 ここでは暗号化/圧縮の有無。立ち時に各エントリが追加で持つ 暗号化のたびに変える使い捨ての値。 同じ鍵で再利用すると安全性が崩れるため毎回変える。(12)+AES-GCM が出力する 16 バイトの認証データ。 これが合わないとデータが改竄/破損とみなす。(16) のバイト数。

定数

対応するAPI候補

  • acs::assetpack::kAcpakHeaderDiskSizeinline constexpr usize kAcpakHeaderDiskSize = 36;
  • acs::assetpack::kAcpakCipherFieldsDiskSizeinline constexpr usize kAcpakCipherFieldsDiskSize = 12u + 16u;

使う場面

.acpak などのアセットを読む側の部品。 pak をマウントして仮想ファイルを取り出す(対になる書き出し側が Writer)。/Writer がヘッダ/file table を memcpy で読み書きする時の境界値。 非鍵を知らないと中身を読めない形にデータを変換すること。 pak(flags=0)では cipher fields は 0 バイト = v1 各ウィジェットを画面のどこにどの大きさで置くかを決めて配置すること。 Layout で行う。と完全一致。

API項目

API項目 1

inline constexpr usize kAcpakHeaderDiskSize = 36
説明
ディスク上のヘッダ長。 magic8+version4+flags4+file_count4+padding4+file_table_offset8+reserved4 = 36。
対応API
acs::assetpack::kAcpakHeaderDiskSize 定数

API項目 2

inline constexpr usize kAcpakCipherFieldsDiskSize = 12u + 16u
説明
鍵を知らないと中身を読めない形にデータを変換すること。時に file table の各 entry が追加で持つ 暗号化のたびに変える使い捨ての値。 同じ鍵で再利用すると安全性が崩れるため毎回変える。(12)+tag(16)=28 バイト。 flags=0 なら 0。
対応API
acs::assetpack::kAcpakCipherFieldsDiskSize 定数

使用例

// ヘッダは構造体 sizeof でなくこの定数でディスク I/O する
ReadBytes(head, kAcpakHeaderDiskSize);   // = 36
// 暗号化 pak は各 entry に +28 バイト(nonce+tag)
