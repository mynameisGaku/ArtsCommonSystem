CWindowsCrashReporter

Windows 専用のクラッシュ報告 インターフェースの裏で実際に仕事をする具象実装。 ここでは OpenXR ローダ等の XR 実装本体。。 gameframework の gameframework 側のクラッシュ報告 backend 抽象インターフェース。 crashwin はその Windows 実装。 を実装し、Windows 標準のデバッグ支援ライブラリ。 MiniDumpWriteDump でミニダンプを生成できる。 の MiniDumpWriteDump でクラッシュ時のメモリ状態を抜き出した .dmp ファイル。 後でデバッガに読み込んでスタックを解析できる。を、合わせて人間が読めるテキスト報告書を書き出します。 直前の クラッシュ前の出来事を時系列で残す短いログ（breadcrumb）。 「どこまで進んでいたか」の手掛かりになる。（クラッシュ前に何が起きていたかを時系列で残す短いログ。 クラッシュ報告に添付して原因追跡に使う。）も最大 32 件まで添付します。 中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。／中身をコピーせず所有権ごと移すこと。 大きなデータを安く引き渡せる。は禁止。

クラス
対応するAPI: acs::crashwin::CWindowsCrashReporter

使う場面

Windows タイトルで、クラッシュや非致命エラーをローカルファイルとして残したい時。 多くの場合は直接 new せず Windows のクラッシュ報告 backend を既定の provider に登録する結線ヘルパ。 起動時に一度呼ぶと本物の backend が使われるようになる。 経由で プロセス内に 1 個だけ存在するインスタンス。 XR ランタイムのように 1 接続前提のものに使う。 として使います。

API項目 5

TResult<void> ReportCrash(const FCrashContext& Context)
説明
クラッシュ 1 件を処理する。 クラッシュ時のメモリ状態を抜き出した .dmp ファイル。 後でデバッガに読み込んでスタックを解析できる。（.dmp）と、C++ の throw/catch による失敗伝搬。 ACS は性能と単純さのため使わず TResult を選ぶ。種別・メッセージ・関数の呼び出しに沿って自動で確保/解放される高速なメモリ。 寿命はスコープに縛られる。・クラッシュ前の出来事を時系列で残す短いログ（breadcrumb）。 「どこまで進んでいたか」の手掛かりになる。を含むテキスト報告書を出力フォルダに書く。
戻り値
成否（成功なら値、失敗なら理由を入れて返す型 Result<T,E>。 例外の代わり。）
使う場面
自前のクラッシュハンドラからプロセスがまだ生きている間に呼ぶ。
使用例

ctx.exception_type = "SEH_ACCESS_VIOLATION";
ctx.message        = "null deref in Foo::Bar";
