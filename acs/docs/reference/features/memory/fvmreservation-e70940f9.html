FVmReservation

巨大な仮想アドレス空間を予約(Reserve)し、必要なページだけ物理コミット(Commit)する低レベル オブジェクトの寿命に資源の確保/解放を結びつける手法。 スコープを抜けると自動で後始末される。 実体を間接的に指す軽い識別子 (多くは整数)。 ポインタの代わりに使い、安全な再利用や stale 検出を可能にする。(VirtualAlloc ラッパ)。 Decommit したページは内部 LRU キャッシュ(16 エントリ、既定の総量上限 64 MiB)に保持し、再 Commit がヒットすればコンポーネントを持つエンティティ群を毎フレーム処理する関数(移動・AI など)。 CSystemScheduler で順に実行する。コールを省く。 中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。不可・中身をコピーせず所有権ごと移すこと。 大きなデータを安く引き渡せる。可。

クラス
対応するAPI: acs::FVmReservation

使う場面

CTlsfAllocator 等の土台として、上限の決まった広大なアリーナを予約だけ先に取り、使う分だけ後からコミットしたい時。 通常は直接使わずメモリの確保/解放のやり方を担当する部品。 用途に応じて差し替えられる。越しに使う。

使用例

auto r = FVmReservation::Reserve(256u << 20);   // 256MB 予約(物理はまだ)
if (r.IsOk()) {
    FVmReservation vm = static_cast<FVmReservation&&>(r.Value());
    vm.Commit(0, 8u << 20);                    // 先頭 8MB を物理割り当て
    void* base = vm.Base();
    vm.Decommit(0, 8u << 20);                  // 返却(実 VirtualFree は LRU エビクト時)
}                                                 // スコープ脱出で Release
