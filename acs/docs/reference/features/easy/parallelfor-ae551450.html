ParallelFor

[begin,end) を全コアで分担して fn(i) を呼び、完了まで待つ（処理が終わるまでその場で待つやり方。 結果がすぐ手に入る代わりに止まる。）。 内部は本格的な暇なワーカーが忙しいワーカーの未処理タスクを奪って実行し、全体の負荷を均す方式。ワーカースレッドを前もって用意し、タスクを投げて使い回す仕組み。 毎回スレッドを作るより軽い。。 並列にできない環境では自動的に順次実行へ本命が使えない時の代替経路。 XR では HMD 未接続時に通常の 2D 画面描画へ切り替えること。。

関数テンプレート

対応するAPI候補

  • acs::easy::ParallelFortemplate<typename Fn> inline void ParallelFor(i32 begin, i32 end, i32 grain, Fn fn) noexcept;
  • acs::easy::ParallelFortemplate<typename Fn> inline void ParallelFor(i32 begin, i32 end, Fn fn) noexcept;

使う場面

大量の独立した計算（炎・煙・火花などを表現する大量の小さな粒子。 1 つ 1 つが位置・速度・寿命を持って動く。更新、画像処理など）を一気に速くしたい時。 各 i は独立して処理し、画面に絵(図形・画像・文字)を出すこと。 レンダリングとも言う。など他の easy 関数を中で呼ばないこと（1 つのプログラム内で同時に進む実行の流れ。 複数あると処理を並列にできる。はメイン専用）。

使用例

// 1000 個のパーティクルを並列更新（描画はしない）
ParallelFor(0, 1000, [&](int i){
    particles[i].x += particles[i].vx * dt;
});
// 描画は戻ってからメインスレッドで
for (int i = 0; i < 1000; ++i) DrawPixel(particles[i].x, particles[i].y, FColor::White);
