スクリプト窓口の概要

ゲームコードから見たスクリプトの単一窓口。 スクリプト VM の純粋仮想インターフェース。 Lua/Wren/Python 等を差し替えるための seam。 CLuaVm がこれを実装する。* を 1 つ保持し、関数呼び出し・ファイル実行・C++ 関数登録・エラー通知をまとめる(Dependency Injection(依存性注入)。 使う実装を外から差し込み、呼び出し側を具体実装に依存させない設計。 CScriptHost は VM を差し替え可能にする。 ポイントを 1 つに絞る)。 vm は所有しない(生成/破棄は ゲームアプリの基底クラス。 CApplication を継承し、シーン管理・固定タイムステップ・シーン遷移を内蔵する。/Scene 側の責任)。 中身をそっくり複製すること。 ACS では高コストや所有権の事故を避けるため、多くの型でコピーを禁止しムーブのみ許す。/中身をコピーせず所有権ごと移すこと。 大きなデータを安く引き渡せる。不可。

クラス

使う場面

ゲーム側で「スクリプトを呼ぶ」窓口が欲しい時。 Cゲーム組み込みで広く使われる軽量スクリプト言語。 C++ を再ビルドせずにロジックを差し替えられる。Vm(実)や GetVm本物の代わりに置く最小実装。 依存ゼロでコンパイル・テストできる no-op 版。()(未統合時)を Init() で差し込んで使う。

使用例

acs::scripting::CLuaVm vm; vm.Init();
acs::game::CScriptHost host;
host.Init(&vm);                              // 実 VM(未統合なら &GetVmStub())を差す
host.RegisterNative("spawn", &Spawn, &world);
if (host.LoadAndRun(L"scripts/quest.lua").IsErr()) { /* 失敗処理 */ }
acs::game::FScriptValue ret;
host.CallGlobalFunction("on_start", nullptr, 0, &ret);
host.Shutdown();                            // vm は delete しない
