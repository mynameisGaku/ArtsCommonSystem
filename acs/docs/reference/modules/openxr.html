CKhronosOpenXrBridgeOpenXR 公式ローダ(Khronos loader)を使った実backend。 共通インターフェース IOpenXrBridge を実装し、HMD やコントローラのポーズを提供する。 コピー/ムーブ不可のsingleton運用前提。クラスCOpenXrBridgeStub「常に未初期化/原点ポーズ/パススルー非対応」を返す stub 実装。 実 backend をリンクしていない状態でも、上位がフォールバック(2D 描画)を書けるようにする placeholder。クラスEXrPlatform想定する XR プラットフォーム(HMD 種別)の列挙。 Init() に渡して指定するか、ActivePlatform() で今どれが選ばれたかを知る。列挙(enum)FXrControllerState左右コントローラ 1 フレーム分の入力スナップショット。 各プラットフォーム差を吸収した最小公倍数(ポーズ+トリガ+グリップ+2 ボタン+スティック)。構造体FXrPoseHMD やコントローラの位置と向き。 向きは quaternion ではなく オイラー角(pitch, yaw, roll)をラジアンで持つ簡素な表現。構造体GetDefaultKhronosOpenXrBridge()プロセス共有の実 Khronos bridge(singleton)を返す。 初回アクセス時に Init() を 1 回だけ自動で走らせる(失敗しても参照は返る)。関数GetDefaultOpenXrBridge()backend に依存せず既定の IOpenXrBridge を返す。 実 backend が InstallOpenXrAsDefault() で登録済みなら実 bridge、未登録なら GetXrStub()(stub)を返す。関数GetXrStub()プロセス内に 1 個だけ存在する静的 COpenXrBridgeStub への参照を返す。 provider 未登録時に GetDefaultOpenXrBridge() が返すのもこれ。関数InstallOpenXrAsDefault()gameframework の既定 provider に、この実 Khronos bridge を登録する結線関数。 以後 acs::game::GetDefaultOpenXrBridge() が stub ではなく実 bridge を返すようになる。関数IOpenXrBridgeXR ランタイム/HMD を抽象化した共通インターフェース(seam)。 ゲームロジックはこの型越しに頭・手のポーズやパススルーを叩き、具象 backend(CKhronosOpenXrBridge / stub 等)は差し替えで選ぶ。 シングルスレッド専用・コピー/ムーブ不可。インターフェースkSubOpenXrRuntimeUnavailable / kSubOpenXrInitFailedInit 失敗時に Result へ載るエラーの細分番号。 301=XR ランタイムが見つからない、302=初期化に失敗。定数(エラー subcode)OpenXrBridgeProvider「既定 bridge を返す関数」の型。 IOpenXrBridge& (*)() noexcept という関数ポインタ。型エイリアスSetOpenXrBridgeProvider()既定 bridge を返す関数(provider)を登録する。 実 backend モジュールの Install* から呼ぶ。 nullptr 登録で stub に戻す。 後勝ち。関数xr_err::kSub_NotImplemented「未実装」を表すエラー細分番号(99)。 stub の Init() や、backend 未統合時に Result へ載る。 他モジュール(ML 等)と番号を揃え、横断で「未実装」を一律に扱える。定数(エラー subcode)
