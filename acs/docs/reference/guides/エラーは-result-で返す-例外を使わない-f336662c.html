エラーは Result で返す(例外を使わない)

ACS はC++ の throw/catch による失敗伝搬。 ACS は性能と単純さのため使わず TResult を選ぶ。(throw/try-catch)を使いません。 失敗し得る関数は 成功値かエラー値のどちらか一方を持つ型。 例外を使わずに失敗を戻り値で伝える（既定のエラー型は FErrorCode）。<T, E>(E 既定は ACS の標準エラー型。 カテゴリ・サブコード・OS エラー値・メッセージ・発生位置をまとめて持つ POD。)を返します。 成功なら値(T)、失敗なら理由(E)が入っていて、呼ぶ側が必ず確認します。

TResult<FFile, EIoError> r = OpenFile("a.txt");
if (r.IsOk()) {
    FFile f = r.Value();    // 成功: 中身を取り出す
} else {
    EIoError e = r.Error(); // 失敗: 理由
}
Ok(value) / TResult が失敗を表す側。 err.subcode で原因を見分ける。 成功側は Ok。(code) で作り、IsOk() で確認、Value() で取り出します。 確認せず Value() を呼ぶと失敗時に条件が偽ならその場でプログラムを止めてバグを知らせる仕組み（ACS_ASSERT 等）。で止まります。
