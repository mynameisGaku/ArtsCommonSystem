# 基盤機能の配置基準

便利な機能を一律にサブシステムへ入れず、状態の所有者と寿命から配置を決めます。

| 形式 | 適する条件 | 例 |
|---|---|---|
| 値型 | コピー可能または局所所有で、外部資源を持たない | 状態の写し、選択肢、要求 |
| 所有者付き管理器 | 一つの所有者が更新し、コールバックやハンドルを管理する | `FTimerManager`、`TEvent` |
| サブシステム | シーンまたはアプリケーションの寿命、フレーム更新、複数利用者の共有窓口が必要 | 入力、音声、アセット登録管理 |
| プロセス共有サービス | OS 状態など、プロセス全体で一つだけ存在する | 時計、低水準ログ出力 |

## 判断項目

1. 誰が生成・破棄するかを一つに決められるか。
2. シーン切替時に破棄すべきか、アプリケーション終了まで残すべきか。
3. フレーム更新が必要か。必要なら更新順とスレッドを固定できるか。
4. 複数利用者が同じ状態を見る必要があるか。
5. 保存やリプレイで個別の決定論状態が必要か。
6. コールバック、アロケーター、資源の解放元を所有者に結び付けられるか。

## 現在の配置

- タイマー: 世代付き識別値と呼出し処理を所有する `FTimerManager` を中核にし、
  ワールド共有窓口は既存のサブシステム集合へ登録した`FTimerSubsystem`が提供する。
  旧`FSceneTimer`は同じ正規実装の互換別名とし、別の待機列や識別値を持たない。
- 乱数: 利用者ごとの決定論状態なので、値に近い局所所有とする。共有の乱数生成器は簡易用途に限定する。
- 固定時間刻み: シミュレーションごとの累積時間を持つ値型とし、実時間の時計やサブシステムへ統合しない。
- ストレージ: アロケーターを所有するサービスとする。一括処理は全操作が成功した場合だけ同じストレージへ反映する。
- 入力: ウィンドウまたはアプリケーションから更新され、複数のコンポーネントが参照するサブシステムとする。
- 資源: アセットの寿命と共有参照を管理する登録管理器またはサブシステムとする。
- 診断: コールバック登録管理器は独立した管理器とする。履歴をフレーム更新する場合だけサブシステムに所有者を設ける。
- 型付きイベント: 発行者が所有する管理器とし、プロセス全体で共有するイベントバスを既定にしない。

この基準により、呼び出しを簡単にするためだけの大域シングルトンは増やしません。必要なら
アプリケーションまたはシーンのサービス集合から、所有者が明確な実体を取得します。
