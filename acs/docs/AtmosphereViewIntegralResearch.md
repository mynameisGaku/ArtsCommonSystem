## 分離する入力と出力

太陽方向と視線方向をともに鉛直上向きとし、地表反射、多重散乱、太陽円盤を含めない単散乱を調べる。
CPUは公開`CAtmosphere::EvaluateSkyRadiance`、GPUは現製品の`EvaluatePhysicalSky`を呼ぶ。
高度、太陽入射量、評価点数を入力とし、線形RGBの放射輝度を出力とする。ゲームやEditorの状態には依存させない。

距離は本書ではkmへ統一する。CPU公開高度はmなので1000倍して渡し、GPUにはkmを渡す。
地表半径は6360km、大気上端高度Hは100km。係数の単位はkmの逆数である。
入射量Sは現製品の平行な太陽光を表す係数であり、太陽円盤の単位立体角当たりの輝度とは区別する。
現APIのコメントには両者を混同し得る「ピーク輝度」という記述があり、単位の統一は別途必要である。

## 解析解

視点高度をh0、散乱点高度をhとする。同じ鉛直光路なので、乗法性により

```text
T(h0,h) T(h,H) = T(h0,H)
```

となり、散乱位置から独立になる。レイリー／ミー密度の積分量をCR／CM、オゾンをCOとすると、

```text
Cj = Hj exp(-h0/Hj) [-expm1(-(H-h0)/Hj)]
CRのHj = 8km、CMのHj = 1.2km
T = exp[-(βR CR + βMext CM + βO CO)]
L = S T [βR PR(1) CR + βMscat PM(1) CM]
```

オゾン密度は高度10／25／40kmで0／1／0の三角形。COはh0より上の残り面積を直接求める。
PR(1)=3/(8π)。ACSのミー位相はg=0.8のHenyey–GreensteinなのでPM(1)=(1+g)/(4π(1−g)²)。
βMext=0.0044、βMscat=0.003996を混同せず、散乱を消散へもう一度加算しない。
入射光子は−太陽方向、出射光子は−視線方向へ進むため、今回の散乱角の余弦は+1である。

S=(1,1,1)の独立した倍精度計算例：

## 先行試験の契約

高度0／1.2／8／10／25／40／80／90／99.9375／100kmと、色別の入射量を使う。
高度100kmでは厳密0、それより下では有限かつ正値を要求する。
初期の相対誤差目標は0.1%。絶対誤差だけで高高度の微小な光を0へ潰す実装を通さない。
GPUの現16点、CPUの標準32点を基準とし、単なる点数増加を修正としない。
CPUの0点指定から1点への互換動作、入射量への線形性、太陽積分の評価点数依存も分離して検査する。

既存の50区間試験は視線の中点近似を固定した消散係数の回帰試験であり、連続積分の精度保証ではない。
視線アルゴリズムを変えると期待値の前提も変わるため、その試験を無説明に削除・許容差拡大せず、
新しい解析解の試験へ係数検査の責務を引き継ぐ必要がある。

別の処理順の不具合として、CPUは太陽遮蔽時のcontinueで視線側の消散更新も飛ばしている。
太陽が届かない場所も奥の散乱光を減衰させるため、散乱源が0であることと媒質が存在しないことは区別する必要がある。
例えば正規化した太陽方向のyが−0.05なら、鉛直上向き光路は地表から約7.965kmまで地球の影になる。
この問題は鉛直上向きの太陽だけでは検出できず、影のある入力の独立積分を別のRedとして用意する。
鉛直光路で高さ0kmと6kmの二視点を選ぶと、その間は全て地球の影なので、L(0)=T(0,6)×L(6)が成り立つ。
T(0,6)は指数密度とオゾンの解析積分で独立に求められる。太陽側の数値積分を正解として複製する必要はない。
旧法の対照には地表側1000区間／6km側940区間を使い、共通の100m幅にして明るい部分の標本位置をそろえる案がある。
これは影区間の消散を切り出す試験であり、製品の点数増加による解決案ではない。実際の交点と標本の一致は別途確認する。

また、区間内の太陽透過率を中点に固定して視線透過だけ解析積分しても、積全体の厳密積分にはならない。
同方向・一定媒質の局所例でも、真の値への倍率はsinh(Δτ/2)/(Δτ/2)>1となる。
密度に沿う求積ではR/Mそれぞれの重みと、同じ標本位置のTview×Tsunを評価し、重みを距離順の区間幅へ読み替えない。

## 影の区間分割と次の反例

視線O+tVと平行な太陽方向Sについて、影円柱は次式の内部になる。

```text
A = |V×S|²
B = (O×S)·(V×S)
C = |O×S|²-R²|S|²
A t²+2B t+C < 0 かつ (O+tV)·S < 0
```

根は相殺の少ないqの式で求め、地表または大気上端までの有限視線へ切る。
影がない場合にもclamp(-B/A,0,L)を幅0の分割点として残し、接触時に一つの求積から二つへ急に切り替えない。
GPUは地表直上の視点O=(0,R+h,0)に限定し、判別式の大きい半径二乗の減算を高度hの式へ展開して補償演算する。
この根の精度を、有限地表判定で保証した厳密な整数符号と同一視しない。
影の手前・奥へ各帯の点数を固定して配るため、影が視線途中にあると積分点数と負荷は増える。

高度40kmの青の透過関係も相対約5.4e-6まで改善した。地上／雲内の画像上のちらつき全般の解決ではない。
この時点のSky.cppは`9E8D74FC30D43FA2EDB31203A9A1F5F658760F2FB587296EC5B545D52B2DB692`、

## 非鉛直の精度に向けた次の検討

共有の密度列積分にも誤差がある。地上水平の8点評価は分子282.937594km／微粒子109.537665kmで、
独立積分282.838135km／109.498922kmより大きい。光学的厚さを指数化するため、密度列の相対誤差をそのまま光の誤差上界にできない。

[Yue 2024の本文](https://acp.copernicus.org/articles/24/5093/2024/)を再確認した。
球面密度を半径変化の積分へ移す考え方は参考になるが、式10で近似が入り、評価範囲での最大0.5%は今回の放射輝度0.1%を保証しない。
近似式を厳密な正解や万能の置換として採用しない。
[mpmathの公式解説](https://mpmath.org/doc/current/calculus/integration.html)も、途中の不連続と端点で急変する関数を区別して扱い、分割や誤差推定だけでは正しさを保証しない例を示している。

次は、密度座標の高高度端に残る対数由来の急変をu=U v(2-v)で緩める変換と、
粗い視線標本が密度の総量を変えないようにする0次の積分条件を検討する。
許容誤差を広げたり、太陽色や散乱係数を調整して反例を消す方針は取らない。

## 端点・密度総量・影判定の追加修正

密度列を二次の座標変換で評価し、上端の補余量を次式から直接求めた。

```text
u = U v(2-v)
1-w = exp(-Δh/H) + U(1-v)²(U+u+2p)/(2rH)
```

丸め済みのwを1から引かない。小さいw側には既存のlog1p相当を使う。
また視線の積分は、密度列Cと密度重みwによる `C Σ(w Tview Tsun)/Σw` とした。
分母には極小の基底密度を含めず、影の標本が0となっても分母から媒質を除かない。
これは密度総量を保存するが、変化する透過率を正確に積分できることの証明ではない。

二次変換だけではCPU1点の鉛直解析形との接続が崩れた。
`vertical-join-red-debug.log`は14成功・1失敗で、水平成分1e-5を加えただけでも新しい段差が出た。
Jの既知一次成分 `1+u/r` を解析積分し、残差だけを求積する方式へ直した。
これによりsun_steps=1／3／9の末尾1点でも、鉛直への接続を保つ。

影の判別式を作る外積にも先行丸めがあった。独立監査の二つの入力を実GPUで再現した。
`shadow-cross-red-debug.log`では、約357mある影が幅0となり、影なしの別入力には約394mの幅が生じた。
外積の積・差から上下位を保持してから判別式を評価する修正後、`endpoint-cross-debug.log`で両反例が通った。
密度総量保存後の`moment-debug.log`は14成功・0失敗で、非鉛直5条件も成功した。

ただし、幅0の分割点を単に頂点へ置く方法は、視線と太陽が平行になると別の不連続を生んだ。
`parallel-join-red-debug.log`で、影のない反平行近傍の緑・青が最大約0.196%跳ぶことを実GPUで確認した。
影なしの全分岐で、有限区間内の最接近位置c0と円柱・昼側平面からの隔たりを使う分割規則へ統一した。

```text
c0 = clamp(-B/A, 0, L)
F0 = C                       （c0=0）
F0 = -Δ/A                    （0<c0<L）
G = max(F0,0) + max(P(c0),0)²
f = clamp(c0 + sqrt(G/A), 0, L)
```

c0=L、またはG>=A(L-c0)²なら、大きい除算をする前にf=Lとする。A=0の影なしもf=L。
通常の影発生時にはG→0となって接触位置へつながり、A→0・C≠0の影なしでは区間端へつながる。
`shadow-gap-debug.log`は15成功・0失敗。反平行近傍の最大相対差は約9e-7まで減った。
一方、A=0=Cへ高度も同時に近づける前方の退化入力はこの連続性の確認範囲外である。
物理的には連続な前方光路も含まれるため、全てを「点太陽の物理的な影の不連続」で説明しない。

## 連続性試験では見えなかった絶対値の誤差

反平行近傍の独立参照は、地表・オゾン境界を分けた適応Simpsonと複合Gaussで一致を確認した。
ε=0は別の一次元式 `Tview×Tsun=Tsun(origin)×Tview²` でも主担当が照合した。
高度20km・太陽の天頂余弦0.05・白色入射・反太陽視線の参照は次の値になる。

```text
参照RGB = (0.032974054863, 0.027415840825, 0.041916772117)
固定2点GPU = (0.032966863364, 0.0272784437984, 0.0418709442019)
固定予算CPU = (0.0329738780856, 0.0274134352803, 0.0419195257127)
```

GPUの緑は約0.501%、青は約0.109%小さい。CPUは今回の0.1%以内。
`antiparallel-red-debug.log`は14成功・1失敗で、ε=0／.0001／.0003／.001のGPU絶対値8比較が不合格となった。
同じ4条件の真の最大隣接差は独立参照で約7.43e-7であり、連続性だけの試験には十分な余裕がある。

現候補はGPUの各可視帯で2点と4点の差を測り、大きい場合だけ密度座標の中央で二分する。
出力には常に4点側を使い、密度総量Cも同じ区間へ合わせる。
独立参照の受入相対誤差0.1%の1/10を求積の推定誤差へ配り、深さ6・最大64分割を実行上限とした。
上限や単精度の二分限界でも未処理区間を捨てず、残った推定誤差を返す。
検証入口はこの値を読み戻し、上限到達を「計算が終わったから合格」と扱わない。

推定差は厳密な誤差上界ではない。2点／4点が同じ誤値を返す正値・平滑関数も独立監査で構成できる。
密度列・透過率の共通誤差や親子分割の接続は別途検査が必要である。
この変更は散乱標本の数と負荷を増やすため、旧16点と同じ実行費用とは主張しない。
GPU実行、Debug／Release全体、通常アプリ・Editor、実解像度の性能と画像、配布物・外部Frameworkの受入はまだ完了していない。

### 誤差制御候補の実行記録と中間保存

`adaptive-debug.log`では反太陽方向の絶対値を0.1%以内へ改善したが、微小な帯の相対誤差を最大値で扱う診断が211比較で不合格になった。
帯・密度ごとの絶対推定誤差へ入射量と散乱係数を掛け、RGBごとに合計して全放射輝度へ換算する形へ改めた。
透過率関数の呼出し箇所も一つのループへまとめ、生成コードが同じ本体を複製する負荷を抑える構造へ変更した。
これだけで生成コードの軽量化が証明されたとは扱わず、実行負荷は別途測る。

`adaptive-weighted-debug.log`は14成功・1失敗。残った5比較は、25／40km薄明の推定誤差4比較と、影なし分割点の端越え1比較だった。
後者は`L=90.3276138305664km`に対し`90.32762145996094km`を返した実GPU Redであり、最後の加算結果にも有限区間への制限を加えた。
`adaptive-endpoint-debug.log`ではこの端越えは通過した。

視線平均も二次変換へ合わせた候補は、上端に寄る変化を拾う一方、分割を変換後vの中央にすると片側へ密度座標の75%を残してしまった。
`adaptive-endpoint-debug.log`は14成功・1失敗、推定誤差211比較が不合格。深さ上限では計算量に余裕があっても特定の枝を打ち切ってしまう。
現在は標本の二次変換を保ち、二分位置を累積密度座標uの中央へ戻した上で、上限を深さ6から最終区間数64へ変更している。
最大区間評価127回は変えず、必要な枝だけ深く評価できる配分とする。保留配列は64要素で、局所メモリ負荷の確認が必要。

この中間保存では未合格を維持する。devへは出さず、追加試験を緩めずに修正を続ける。
推定誤差は共通の密度列誤差などを含まないため、独立参照・連続掃引・実画面の受入を省略しない。
