# Project Settings のパッケージ情報

`Project Settings > Distribution` は、任意の `Config/PackageMetadata.json` にあるパッケージ情報を編集します。

## スキーマ

スキーマバージョンは 1 です。発行者、説明、著作権表示、サポート URL を保持します。入力ファイルは厳密な UTF-8、2〜65,536 バイト、最大入れ子深度 8 です。未知フィールド、重複フィールド、コメント、末尾の余分なデータ、再解析ポイントを拒否します。

サポート URL は正規化済みの絶対 HTTPS URL だけを受理します。各フィールドは定義済みの文字数上限を超えられません。

## 適用と取り消し

編集値は準備領域へ保持し、`Apply` で全フィールドをまとめて検証してから保存します。`Revert` は保存済みスナップショットへ戻します。4 フィールドがすべて空の場合は任意設定ファイルを削除し、未設定状態へ戻します。

読み込みに失敗した場合は編集欄、`Apply`、`Revert`を無効にし、ファイルを修復してから`Retry`で読み直します。不正、曖昧、または再解析ポイント経由の既存ファイルを既定値で上書きしたり、自動修復したりしません。

未適用の変更がある状態でProject Settingsを閉じる場合は、適用、破棄、取り消しから選びます。適用を選んだ場合は保存成功後だけ閉じ、失敗時は編集内容を保持します。破棄は保存済みスナップショットへ戻して閉じ、取り消しはウィンドウを開いたままにします。

保存時は読み込み時の生バイト列から得た指紋値を照合し、公開直前にも同じファイルが保たれていることを確認します。別の変更が入っていた場合は上書きしません。同じディレクトリの一時ファイルへ書き、置換または移動で公開します。競合したバイト列を安全に正本へ戻せない場合は、`PackageMetadata.json.tmp-recovery-<操作>-<GUID>`として保持し、診断へ場所を含めます。所有を証明できない復旧ファイルを削除しません。

## 未設定と不正なファイル

`PackageMetadata.json`が存在しない場合は未設定として読み込みます。パッケージ事前検証では`PACKAGE_METADATA_MISSING`を記録し、Shippingでは警告、その他のプロファイルでは情報として扱います。有効なファイルが空の場合は`PACKAGE_METADATA_EMPTY`です。

既存ファイルのスキーマ、UTF-8、フィールド、値、サイズまたはパスが不正な場合は`PACKAGE_METADATA_INVALID`でパッケージ作成を停止します。不正なファイルを削除または置換するには、先に内容を明示的に修復して再読み込みする必要があります。

## パッケージへの反映

パッケージ作成機能は `Config` のスナップショットからメタデータを読み、非公開の準備領域内にある実行ファイルと `package-manifest.json` へ反映します。バージョン、アイコン、署名、ストア認証情報はこのファイルへ保存しません。
