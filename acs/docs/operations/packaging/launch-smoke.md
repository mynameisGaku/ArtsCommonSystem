# 起動確認プロトコル

`PackageLaunchSmoke` は、検証済み配布物が描画開始まで到達し、正常終了できることを非対話で確認します。`package`はZIP公開後に同じ起動確認を実行し、`smoke`は既存ZIPへ単独で再実行します。

## 準備完了通知

起動側は暗号学的乱数生成器で32バイトの値を生成し、256ビットの小文字16進表記として環境変数 `ACS_PACKAGE_SMOKE_TOKEN` だけで実行ファイルへ渡します。実行時は64文字すべてが`0`〜`9`または`a`〜`f`であることを検証します。

`CApplication`は次の順序を完了した後に限り、標準出力へ準備完了通知を1行だけ書きます。

1. ウィンドウと描画器を初期化する。
2. `OnStart`を完了する。
3. 最初のフレームで`OnCustomFrame`を呼ぶ。
4. `OnCustomFrame`が`false`を返す標準描画経路では、`BeginFrame`、`OnRender`、`EndFrame`を順に実行し、`EndFrame`による送信と表示を成功させる。
5. `OnCustomFrame`が`true`を返すカスタム描画経路では、派生側がコマンド送信と表示まで完了したという契約を採用する。この場合、`CApplication`は実行継続中であり、描画デバイスが存在して動作可能な場合だけフレーム完了とみなす。
6. 完了した経路に対して`ACS_PACKAGE_SMOKE_V1 READY <nonce>`を出力し、終了処理へ進む。

カスタム描画経路は`BeginFrame`、`OnRender`、`EndFrame`を実行しません。派生側で送信または表示に失敗した場合は、`Quit()`を呼んでから`OnCustomFrame`で`true`を返し、準備完了通知を抑止します。

`<nonce>`は起動側が渡した値と完全一致しなければなりません。通知がない、余分な文字がある、値が異なる、同じ通知が複数ある場合は失敗です。通知の検出は標準出力の保存上限とは別の逐次認識器で行うため、8 MiBを超えた後に現れた重複通知も失敗になります。

## 成功条件

次の条件をすべて満たした場合だけ成功します。

- 非公開ZIPの検証と展開が完了した。
- 実行ファイルを非表示で開始できた。
- 正しい準備完了通知をちょうど1回受信した。
- ルートプロセスが終了コード0で終了した。
- 継承された子孫プロセスを残していない。
- 非公開の準備領域を削除できた。

シーン起動、描画送信、表示、終了コード、後片付けのいずれかを確認できない場合は、成功として扱いません。

## 時間と出力の上限

起動期限の既定値は45秒です。`--timeout-seconds`には1〜300秒を指定できます。標準出力と標準エラー出力は、それぞれ最大8 MiBまで診断用に保持します。

```pwsh
dotnet run --project tools/acspackage -- smoke `
  C:\Games\MyGame\Build\Packages\MyGame-1.0.0-win64.zip `
  --report C:\Games\MyGame\Build\Packages\smoke-report.json `
  --timeout-seconds 45 `
  --max-extract-mib 16384
```

## プロセスの封じ込め

Windowsではルートプロセスを一時停止状態で作成し、終了時に全プロセスを終了するジョブオブジェクトへ割り当ててから実行を再開します。これにより、最初の命令とジョブオブジェクトへの所属の間に子プロセスが外へ出る隙間を作りません。

通常の起動確認はシェルを経由せず、引数、資格情報、起動動詞、対話的な標準入力を渡しません。標準入力は`NUL`へ接続し、コンソールを作らず、`SW_HIDE`を指定します。標準出力と標準エラー出力に必要なハンドルだけを明示的に継承します。

認証済みトークンを受け取った`CApplication`は実際のHWNDとスワップチェインを作成しますが、ウィンドウへ`ShowWindow`を実行しません。Windowsでは起動確認の間だけ`SEM_FAILCRITICALERRORS`、`SEM_NOGPFAULTERRORBOX`、`SEM_NOOPENFILEERRORBOX`を有効にし、終了時に元のエラーモードへ戻します。

時間切れ、取り消し、監視失敗が発生した場合はプロセスツリー全体を終了し、終了を待ち、標準出力と標準エラー出力を回収してから準備領域を削除します。ルートプロセスが正常終了した場合も、継承された子孫プロセスを終了してから出力を回収します。

子プロセスの環境変数は空の状態から必要項目だけを構成します。`PATH`はWindowsのシステムディレクトリだけを指し、`TEMP`、利用者領域、管理ツール領域は非公開の準備領域へ向けます。

## レポート

既定ではZIPと同じディレクトリへ`<package-name>.package-report.json`を書きます。既存レポートが通常ファイルなら、`WriteThrough`を使う一時ファイルから置き換えます。レポート先をZIP自身にすることはできません。

スキーマバージョン1のレポートには、ZIP名とSHA-256、Package ID、Build ID、`profile`、実行ファイル、ファイル数、展開後サイズ、Asset PackのSHA-256、Cook済みアセット数、起動契約、終了コード、上限、各確認結果、診断を記録します。失敗時だけ標準出力と標準エラー出力の制限付き抜粋を含め、乱数値、非公開パス、ZIPの絶対パス、レポートの絶対パスは置換してから保存します。

成功レポートには時刻、乱数値、非公開パス、実測時間を含めないため、同じZIPと同じ上限から同じ内容を生成できます。`package`はZIPを公開した後に起動確認を行うため、起動確認が失敗しても作成済みZIPを削除しません。失敗内容は終了値とレポートで区別します。

[起動確認用の非公開展開](private-extraction.md)と[パッケージ作成の概要](overview.md)も参照してください。
