# 学習サンプル移行

ACS の `engine/CMakeLists.txt` には68件の学習サンプルが登録されています。現在のソースツリーには対応する `samples` ディレクトリがないため、移行状態は保留です。保留は移行完了を表さず、登録、実装、検証の対応関係が未完了であることを表します。

## 通常の構成

移行が完了するまでは、通常の構成で学習サンプルを無効にします。

```pwsh
cmake -S .\engine -B .\Intermediate\vs -DACS_BUILD_SAMPLES=OFF
```

`ACS_BUILD_SAMPLES=ON`では、`ACS_ONLY_SAMPLE`を適用した後に対象となる登録だけを確認します。対象のディレクトリまたは`CMakeLists.txt`が存在しなければ構成を停止します。`ACS_ONLY_SAMPLE`が空なら68件すべてが対象です。一致する登録がない値を`ACS_ONLY_SAMPLE`へ指定した場合は対象が0件となるため、構成時の欠落検査だけでは全件監査になりません。

## 台帳の監査

登録名、実在ディレクトリ、`CMakeLists.txt`、重複、未登録ディレクトリを次の監査で照合します。

```pwsh
python .\scripts\audit_sample_registry.py --self-test
python .\scripts\audit_sample_registry.py --root . `
  --json-output .\Intermediate\sample-registry-audit.json
cmake --build .\Intermediate\vs --target acs_sample_registry_check
```

`acs_sample_registry_check`と`ACS.SampleRegistryAuditSelfTest`は、`ACS_BUILD_TESTS=ON`で`tests/CMakeLists.txt`が読み込まれた場合だけ登録されます。`acs_sample_registry_check`は対象を明示してビルドした時に台帳全体を監査し、`ACS.SampleRegistryAuditSelfTest`はCTestで選択して実行した時に監査器自体を検証します。`ACS_BUILD_TESTS=ON`かつ`ACS_BUILD_SAMPLES=ON`の構成では、台帳全体を監査する`ACS.SampleRegistryAudit`もCTestへ登録されますが、CTestで選択して実行するまでは監査を開始しません。いずれもCMakeの構成時には実行されません。監査の失敗は削除の許可ではなく、保留を維持する根拠です。

## 置換台帳

旧サンプルごとに、少なくとも次の項目を1行で管理します。

| 項目 | 記録する内容 |
|---|---|
| 登録名 | `engine/CMakeLists.txt` の `acs_add_sample` 名 |
| 学習目標 | そのサンプルだけで学ぶ中心概念 |
| 前提 | 先に完了しているサンプルと必要な機能 |
| 公開API | 使用するモジュール、型、関数、定数 |
| 構成条件 | バックエンドと任意機能の有効・無効 |
| 入力 | アセット、設定、操作 |
| 期待結果 | 終了値、ログ、画面、状態変化 |
| 置換先 | 新しいサンプル名と検証状態 |

説明だけが存在する項目、コンパイルだけに成功した項目、画像だけを取得した項目は完了にしません。旧サンプルが担っていたAPIと構成条件の両方に置換先が必要です。

## 学習順

新しいサンプルは責務別の学習系列へ分け、各系列では画面を必要としない最小例を先に置きます。

1. `01_foundation`: 型、結果値、メモリ管理、コンテナ、デリゲート、イベント、タイマー、スレッド処理
2. `02_application`: アプリケーションの生存期間、ウィンドウ、入力、ファイル、保存領域、アセット
3. `03_2d`: スプライト、文字描画、音声、シーン、ノード、コンポーネント、衝突判定、物理、タイルマップ、UI
4. `04_3d`: メッシュ、カメラ、マテリアル、ライト、シャドウ、アニメーション、アセット読み込み
5. `05_rendering`: RHI、シェーダー、バッファー、テクスチャ、描画先、描画後処理
6. `06_services`: ネットワーク、スクリプト、計測情報、クラッシュ報告、パッケージ、任意バックエンド
7. `07_tools`: ImGui、MVVM、ACS Editor拡張、アセットツール
8. `08_integration_labs`: 複数モジュールを組み合わせる統合演習

1つのサンプルでは1つの中心概念を扱い、ACSの公開APIと既存のモジュール、メモリ管理、イベント、ビルド機構を使用します。サンプル専用の代替実装は追加しません。

## サンプルごとの完成条件

各サンプルには、学習目標、前提、構成と実行方法、期待結果、代表的な失敗、練習課題を記載します。重要な契約はサンプルだけに置かず、単体テストにも固定します。

- 画面を使わないサンプルはDebugとReleaseでビルドし、終了値と主要な出力を確認します。
- 描画サンプルは起動確認に加え、代表フレーム、描画領域、入力後の状態を画像で確認します。
- Raw DX12とDiligentを使うサンプルは、対象バックエンドごとに構成、ビルド、実行を確認します。
- 任意機能は有効・無効の両方を確認し、無効時は明確な省略または非登録にします。
- 単一ヘッダー配布物と通常ヘッダー配布物は、独立した利用側プロジェクトでビルドとリンクを確認します。

代表画像は同じ構成と入力で再取得できるようにし、画像の生成に必要なアセット、設定、操作手順をサンプル内へ残します。画像の一致だけでAPI、リソースの寿命、エラー処理の検証を代用しません。

## 置換の順序

1. 68件の置換台帳を確定します。
2. 共通の最小CMake、エントリーポイント、README、検証規則を用意します。
3. `Foundation`、`Container`、`Memory`、`Event`、`Timer`、`Threading`、`Platform`、`Asset`、`Scripting`を画面不要の例から置換します。
4. ウィンドウ、2D、3D、RHI、UI、`Editor`の順に対話的な例を置換します。
5. 任意機能を個別の例へ分け、最後に統合演習を追加します。
6. すべての置換と検証が完了した変更でだけ、旧登録と旧ディレクトリをまとめて削除します。

移行途中では新旧を併存させ、構成可能な状態を保ちます。欠落した登録を削るだけの変更や、旧番号だけを別名へ移す変更は置換に数えません。

## 回帰ゲート

現在の`audit_sample_registry.py`が検査する範囲は、`engine/CMakeLists.txt`の登録、`samples`ディレクトリ、各`CMakeLists.txt`、重複登録、未登録ディレクトリです。廃止した旧サンプル名の再導入と、生成リファレンス内のリンク先はまだ検査対象ではありません。この状態では移行完了または旧サンプル削除のゲートを満たしません。

旧サンプルを削除する変更には、次の検査を同じ回帰ゲートへ追加します。

- 廃止名の固定一覧を持ち、CMake登録、`samples`のディレクトリ名、ACS文書、リファレンス生成元へ旧名が再導入された場合に失敗する。
- リファレンス生成後に全ローカルリンクを列挙し、サンプルへのリンクが新しい配置だけを指し、旧配置や存在しないファイルを指さないことを確認する。
- 新しいサンプル名、CMake登録、実在ディレクトリ、生成リファレンスを同一のソース版で照合し、どれか一つだけが更新された状態を失敗にする。

これらの検査が実装され、旧名を含む検査用データで失敗し、新配置だけの検査用データで成功するまでは、削除条件の「旧参照がない」を手作業の確認だけで完了扱いにしません。

## 削除条件

旧サンプルまたは再現用ツールは、次の条件がすべて成立するまで削除しません。

- 68件すべてに、APIと構成条件を満たす置換先がある。
- Debug、Release、Raw DX12、Diligent、対象となる任意機能の検証表に未確認がない。
- 対話的サンプルの代表画像と主要操作後の状態を確認している。
- チュートリアル、クイックスタート、リファレンス、README、ソリューション生成、配布物に旧参照がない。
- 独立した利用側プロジェクトで通常ヘッダーと単一ヘッダーのビルドとリンクが成功する。
- 削除対象が構成・コンパイル、検査、コード生成、配布検証、画像再取得に不要であることを確認している。
- 削除後にも同じ不具合を再現できる最小アセット、設定、取得手段、監査スクリプトが残る。

実行時に不要なファイルでも、生成物がない状態からの構成、検証、配布、画像再取得に必要ならACSの再現資産として保持します。削除は対象一覧を固定し、隔離した同一のソース版で全検証を通した後に適用します。
