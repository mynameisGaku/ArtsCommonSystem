# ノード所有権と構造安全性

`ANode` の親子関係は「親が `TObjectPtr<ANode>` で子を強参照し、子は親を非所有
ポインタで参照する」単一親ツリーです。構造を変更するときは、この不変条件を維持する
API を使います。

## 失敗を検出する子追加

外部入力、エディタ操作、生成スクリプトなど、追加失敗を処理する必要がある経路では
`TryAddChild` を使います。

`TryAddChild` は次を拒否します。

- null、自分自身、祖先の追加による循環
- 既に親を持つノードの追加による多重親
- 親または子が破棄予定のとき
- 追加後の深度が `kNodeMaxTreeDepth` を超えるとき

`AddChild(TObjectPtr<ANode>)` は既存コード向けの互換 API です。成功時は従来どおり
追加した子を返します。不正な追加は警告を出して拒否し、従来の null 入力と同じく
追加先自身を返します。結果に応じた処理が必要な新規コードでは `TryAddChild` を
優先してください。

## 深度上限

深度は root を 0 とする親子 edge 数で数え、最大値は `kNodeMaxTreeDepth` (512) です。
これは更新、描画、構造変更、所有参照の解放でネイティブスタックが枯渇することを
防ぐ共通の安全境界です。`World()` の transform 合成自体は反復処理であり、上限境界
でも再帰スタックを消費しません。`Reparent` も移動後に上限を超える要求を拒否します。

シリアライズやネットワークなどからツリーを復元するコードも、独自に親ポインタを
操作せず、この不変条件と同じかそれより厳しい入力上限を適用してください。
