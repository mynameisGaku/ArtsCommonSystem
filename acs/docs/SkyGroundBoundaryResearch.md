## 地表境界の実装と実GPUの証拠

製品の`CSky::Init`と`RenderPhysicalAtmosphere`を、通常C++の試験実行ファイルから呼ぶ。
シェーダーの複製でなく、製品の頂点・画素シェーダー、定数設定、実描画を検査する。
正射影の2×2画素をRGBA32Fへ出力し、各描画の提出とGPU完了後に全画素を読み戻す。
GPU初期化失敗・提出失敗・読戻し失敗は試験失敗であり、未実行を成功としない。
実測環境はRaw DX12 / NVIDIA GeForce RTX 4070 SUPER。

添付の「検証可能な設計」スキルに従い、カメラ・太陽・地表反射率を明示した境界へ試験を置いた。
既存のRHI・カメラ・テスト基盤を使い、新しい公開API、共有状態、サブシステムは追加していない。
全試験の数分間の実行を待たずに再現できるよう、同じ試験ファイルを
`acs_sky_ground_tests` / CTest `ACS.SkyGroundGpu`としても登録した。
この試験は描画可能なGPUを必須とする。登録先は通常の単体試験と単独のGPU試験の両方である。

最終の試験ファイルは2試験で構成する。上の公開描画13条件に加え、製品HLSLをファイルから抽出し、
検査入口だけを足す計算シェーダーで10幾何条件・12光学的深さを検査する。
元の関数本体を試験用に複製せず、実行時の定数バッファを使って定数計算への置換を避ける。
後者はGPUが復元した方向そのものを読み戻し、独立した倍精度の球方程式へ渡す。
3次元の方向、非単位長、地表の太陽遮蔽、上端接線、級数の切替内外も含む。
ただし上端接線の呼出しは定数評価され得るため、実行時入力によるGPU分岐の証明とはしない。

### 高度70kmでの反例と期待値の訂正

独立監査で、地表相対座標へ変えただけでは、高度70km、
方向`(0.9891135096549988,-0.14715442061424255,0)`の判別式が負へ丸まることが判明した。
厳密な参照では`D=+0.011591564`、入口は約946.095300kmである。
当初は公開描画へ同じ方向を指定して調べたが、CPUとGPUの正規化は同じ値を返さなかった。
GPUで復元された方向`(0.98911345005,-0.147154405713,0)`は実際に地平線の外側である。
この公開描画の失敗を交差判定の不具合根拠にした説明は撤回し、その期待値を採用しない。
`red-high-horizon-input-debug.log`などは、この切り分け過程のログとして保持する。

最終的には方向を実行時CBから直接渡す検査で切り分けた。
同じ元方向に対し、補償呼出しを外すと入口-1、補償を使うと946.095336914kmとなる。
GPU自身の方向も別に読み戻して参照へ渡すため、CPUのカメラ復元との一致を前提にしない。
内外で隣接するfloat方向も検査し、判別式へ許容差を足して誤って交差させる回避を排除する。

### 採用した計算と適用限界

地表半径をR、地表相対座標をp、球半径をr、方向をdとし、惑星中心からの位置を`P=p+(0,R,0)`とする。
`a=dot(d,d)`、`b=dot(p,d)+R*d.y`、
`c=dot(p,p)+2R*p.y+(R-r)*(R+r)`、`D=b*b-a*c`で球方程式を作る。
Rに0.1mの高度を足して先に丸める処理をなくし、正規化後のdの長さも1と決めつけない。
内向きの小さい根は`c/(-b+sqrt(D))`とし、大きい値同士の差を避ける。
球面上で内向きなら距離0で終わり、外向きや出発点の接線は接触だけで遮蔽しない。
上端球面の重根は`-b/a`を直接返し、分数形の0/0を避ける。

北極上の視点では、`D=r^2*dy^2-c*(dx^2+dz^2)`の恒等式を用いる。
係数生成から主値・下位の二項で保持し、最後の差まで下位桁を捨てない。
[Ogita・Rump・Oishi、2005年、§2–3](https://ogilab.w.waseda.jp/ogita/math/doc/2005_OgRuOi.pdf)の
和・積の誤差回収を参照し、仮数24bitを12bitずつに分ける部分は整数のビットマスクで実装した。
原論文の加減乗算の丸め、範囲超過、最小値未満の丸めに関する前提をGPUへ無条件に移さない。
主値へ下位を足し戻して再正規化した案はReleaseの実GPUで下位が0になったため不採用とした。
最終版は二項の和としてそのまま保持する。これは完全な倍精度型や厳密演算の実装ではない。
二項の積は下位同士の積を省略するため、任意の二項値を受け取る汎用演算ではない。
現在の経路では下位は主値の丸めから生じ、強い相殺は最後の差に限り、その後に二項の積を行わない。
実行DXBCにpreciseがあることは確認したが、下位消失を生む具体的なドライバー命令までは未特定である。
符号を許容差で書き換える処理は追加していない。

高度も`(|P|^2-R^2)/(|P|+R)`へ有理化する。
地表の太陽透過は球対称性を使って地表原点へ回転し、従来の1m持ち上げを除去した。
これは均質な球対称大気のみに適用する。地形・雲・空間変動する媒質を回転で代用してはいない。

区間平均透過率`(1-exp(-x))/x`は、xが0に近づくと1へ近づく。
旧式の`max(x,1e-6)`はこの極限を壊すため、0以上1/8以下では
`1-x/2+x^2/6-x^3/24+x^4/120`を使う。
交代級数の打切り誤差は`x^5/720 < 4.24e-8`であり、この値域の単精度1ULPより小さい。
最初の案は0.01で切り替えたが、その直上ではexp側の誤差が小さい分母で増幅されたため不採用とした。
級数の打切りとexp側の丸めの両方を考慮し、最終12条件は倍精度expm1参照に絶対2e-6以内で一致する。
これは実数での打切り誤差であり、GPUの丸め誤差の保証ではない。
それ以外は分母を置換せず元の比を計算する。

[PBRTの丸め誤差の解説](https://www.pbr-book.org/4ed/Shapes/Managing_Rounding_Error)が指摘する通り、
根の式だけを安定化しても、係数を作る時点の誤差は残る。
HLSLの`precise`は[Microsoftの仕様](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/dx-graphics-hlsl-variable-syntax)に従い
式の再結合や暗黙の積和融合を抑える目的で使う。倍精度化や誤差ゼロの指定ではない。

北極から離れた位置でcが相殺する問題は残る。元の70km反例は上記の固定入力GPUで解決したが、
補償計算も厳密な符号判定を全域で保証しない。中間版の独立模擬では
`h=13.25, d=(0.7763671875,-0.050140380859375,2^-27)`の真の判別式が約`-9.3656e-12`なのに
0へ丸まる例が見つかった。これは素朴な倍精度参照も0になる条件であり、厳密な参照と画素被覆の課題へ残す。
大気圏外からの入口区間も未実装だが、現公開入力は0–100kmへ制限される。
この限定修正を全高度・全位置の幾何保証へ拡大しない。
8点の太陽光路積分と16点の視線積分の精度、多重散乱、太陽円盤、他の描画方式、
Editor/外部Frameworkの操作実行、実解像度の性能・連続画像は今回の数値合格に含めない。
配布物の再生成と外部Frameworkへの再導入も未実施。通常C++の検証プロジェクト、反射DLL、
Editor ABIのDebug/Releaseビルドは通過したが、これを配布一式の互換性検証とは扱わない。

最終候補の独立監査は数式と試験を別担当で実施し、新たな取り込み阻害所見はなかった。
Sky.cppのSHA-256は`E2F52B39B275FA250C715F328796150D40E90E07137C85A97CCDD4A02AF8EA73`、
試験は`4EFB91C7E9A9D5815F5D126D5D1EE9F75B259384B38BC1A01DD1C7EB8D5BC2C7`。
型名などのC++規約監査はrender/gameframeworkの573ファイルで通過した。

### 次の小単位: 媒質の係数契約と光路積分

今回の地表修正には混ぜず、次に同じ大気モデルの経路間不一致をTDDで扱う。
主担当と別の読み取り専用監査で、SkyとAtmosphere CPUはミー消散を
`0.003996+0.0044=0.008396/km`、Atmosphere共通GPUは`0.0044/km`としていたことを確認した。
前者も高吸収モデルとしては物理的に可能だが、同じモデルというコメントの契約と一致しない。
共通GPUに合わせるなら吸収は`0.0044-0.003996=0.000404/km`となる。
[Bruneton著者デモ](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/demo/demo.cc.html)の
消散`0.00444/km`と吸収`0.000444/km`は別の既定値であり、両者を混同しない。

まず高度0・1.2・8・10・25・40kmの媒質出力を、密度と散乱係数の違いも換算して照合する。
次に鉛直光路の指数密度の解析積分とオゾンの面積を期待値として、光路積分の精度を検証する。
既存8点式との一致と、解析解に対する精度合格は別の試験にする。
単位・係数の契約と積分法を分け、見た目の係数変更で誤差を相殺しない。

## 採用判断と受入範囲

| 項目 | 判断 | 理由と受入範囲 |
| --- | --- | --- |
| 地表境界 | 今回の限定修正を採用。公開13条件と計算核の試験を単独GPU通過 | 距離0・微小高度・記録した地平線内外が対象。極微接線や任意位置などの残件は未合格 |
| 太陽円盤 | 未解決のまま設計を記録。今回は変更しない | 合成だけでなく入力単位、半精度格納、部分遮蔽、画素内積分の契約が未成立。TDD試験はまだ未実装 |
| 光路積分の数値精度 | 次の小単位で検証 | 標本数・区間配分・密度積分精度の合否を、地表境界の合格へ混ぜない |
| 空全体の物理的な正しさ・出荷品質 | 未認定 | 地表境界が通過しても、円盤と積分精度の残件は解消しない |

地表境界の受入では、円盤合成より前の散乱・地表反射の契約を検証する。
製品の最終画素を読む場合は、太陽円盤と人工光彩が対象画素へ重ならない方向を選び、
雲・ディザ・トーンマッピングなどの混入条件も固定して記録する。
地表境界を通すために、今回対象外の円盤式を変更しない。
円盤が重なる最終画素での「地球越しの直射が0」という条件は、将来の円盤修正の受入に残す。

境界側の解析条件は次のとおりである。ここでは新しい交点算法を指定しない。

- 視点が地表上で地面へ向く場合、視線の媒質区間は距離0で終わる。
  したがって、その視線区間の散乱は0、地表までの透過率は1となる。
  ただし地表を照らす太陽光路は別であり、その減衰まで1とはしない。
- 地表上から外へ向く場合は、出発点への接触だけを理由に空を遮蔽しない。
- 正の高度から地表へ近づく極限と高度0を比較する。
  地表に到達する視線と接線近傍の分類は、独立した幾何の期待値で確認する。
- 地表までの透過率を保持し、地表反射を消さない。
  将来の太陽直達項の可視性と、地表へ届く視線の透過率を同じ値で代用しない。

製品GPUの失敗・修正後の読戻し・既存art skyの回帰と計算核の試験が揃った上記条件のみを通過とする。
独立したCPU計算やソース文字列の一致だけで製品GPUの合格を宣言しない。

## 放射照度Eと放射輝度Lの独立導出

Eは単位面積が受け取る放射束、Lは単位投影面積・単位立体角あたりの放射束である。
それぞれの単位はW/m²、W/(m²·sr)。分光量を扱うなら双方に/nmが加わる。
照度・輝度という測光量を用いる場合はlux・cd/m²となり、放射量との色変換を別途定義する。
[Brunetonの公式単位定義](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/definitions.glsl.html)もこれらを区別している。

大気圏外で遮蔽されていない、角半径alphaの均一円盤を考える。
受光面の法線は太陽中心方向と一致し、円盤全体が受光面の前方半球内にあるものとする。
thetaは太陽中心からの角度、phiは方位角で、立体角の要素は
`dOmega = sin(theta) dtheta dphi`となる。Eの定義から、コードと独立に次を得る。

```text
E = integral_disk L cos(theta) dOmega
  = 2 pi L integral_0^alpha cos(theta) sin(theta) dtheta
  = pi L sin(alpha)^2

q = 1 - cos(alpha)
sin(alpha)^2 = 1 - (1 - q)^2 = q (2 - q)
L = E / [pi q (2 - q)]
```

分母は投影を含む量であり、円盤の立体角`Omega = 2 pi q`とは異なる。
alphaは直径でなく角半径、qはラジアンでなく`1 - cos(alpha)`である。
Eを固定して半径を変える場合、Lはこの投影量に反比例する。
Eが正でqが0なら有限の均一円盤輝度は定義できないため、許容半径と無効入力の扱いも契約が必要となる。

散乱で使う正規化された位相関数pはsr^-1、散乱係数betaは距離^-1、
光学的深さ`tau = integral beta_ext ds`と透過率`T = exp(-tau)`は無次元である。
平行光近似の散乱源`E T_sun beta p`を距離について積分するとLの単位になる。
有限円盤の厳密な散乱源は`beta integral_disk L T_sun V_sun p dOmega`であり、
円盤中心のEとpだけを使う式は小角・平行光の近似である。
この光源方向の積分と、表示画素内の円盤AAは別の計算である。

## 原論文・公式実装との対応と差

| 根拠 | 確認した内容 | この経路への判断 |
| --- | --- | --- |
| [Bruneton・Neyret原論文、2008年、§2.2・式(5)から(11)](https://diglib.eg.org/server/api/core/bitstreams/8526ee8e-15ba-4779-b7ba-2f8334772eb2/content) | 直達光、地表反射、散乱を加算し、それぞれの光路に透過を適用する。地表に遮られた直達光は0 | 散乱を太陽色で置換する合成の根拠にはならない。本文の直達方向の表現と、有限円盤の画素AAは区別する |
| [公式model.cc、GetSolarRadiance](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/model.cc.html) | `solar_irradiance / (PI * alpha * alpha)` | 小角近似。均一円盤の厳密な正対照度契約は`pi * sin(alpha)^2`で独立に評価する |
| [公式demo.glsl](https://ebruneton.github.io/precomputed_atmospheric_scattering/atmosphere/demo/demo.glsl.html) | 円盤内で`radiance + transmittance * GetSolarRadiance()`とし、その後に地表などの遮蔽物を合成する | 加算と遮蔽の順序を参照する。円盤判定は方向の閾値であり、画素積分の保存保証にはならない |

公式demoには近似的な柔らかい影や見た目の補助もあり、公式の画素値全体を厳密解とはしない。
また、本経路の単一散乱による直接積分は、原論文の多重散乱を含む事前計算全体と同等ではない。
位相関数や媒質係数の個別差、積分の数値精度は本書の採用判断では修正・認定しない。

基準スナップショットでは、Sky.hの`sun_intensity`は「線形HDR放射輝度」と説明される一方、
散乱源と`albedo * sun_intensity * cos / pi`の地表反射では放射照度相当として使われていた。
さらに円盤では同じ入力をそのまま色として使い、`lerp`で散乱結果を上書きしていた。
入力の物理単位を説明だけで置き換えることも、円盤に除算だけを追加することも採用しない。

将来のphysical入力は、大気圏外・太陽中心に正対する面の放射照度であり、
大気減衰前・露出適用前かどうかを明記する必要がある。RGBの基底と共通の数値尺度も必要である。
以下のE=22は提示された入力条件の計算であって、呼出元の22を実測W/m²と認定するものではない。
実際の呼出元とHDRターゲット形式は、この限定文書作成では調査していない。

## 既定qでの数値と半精度の問題

本節の数値はすべて、指定された既定値`q = 1.08e-5`と`E = 22`を起点とする。
qを倍精度の実数として計算した解析値であり、製品GPUの測定値ではない。
前回監査の`alpha = 0.00465 rad`という別の例からqを逆算していない。
実装時には実際に渡すfloatのqとGPUでの丸めを含めて許容誤差を決める。

| 量 | 既定qによる解析値 |
| --- | --- |
| `alpha = 2 asin(sqrt(q / 2))` | 約0.00464758419828 rad |
| `K = pi q (2 - q)` | 約0.0000678580348822 |
| 円盤放射輝度`L = 22 / K` | 約324206.2644 |
| 半精度の最大有限値`M = (2 - 2^-10) * 2^15` | 65504 |
| `L / M` | 約4.949411706 |
| 無減衰・円盤単独で半精度に収まる照度上限`M K` | 約4.444972717 |
| 格納前の共通倍率の上限`M / L` | 約0.2020442144 |

RGBA16Fは成分ごとに半精度の浮動小数点を使う。
[DXGI形式の定義](https://learn.microsoft.com/en-us/windows/win32/api/dxgiformat/ne-dxgiformat-dxgi_format)と
[最大有限値の説明](https://devblogs.microsoft.com/dotnet/introducing-the-half-type/)に照らすと、
透過率1で解像されたこの円盤内部を、上記の尺度のままRGBA16Fへ格納できない。
格納時の丸め・非有限値化などの実際の挙動はGPU試験待ちだが、表現範囲超過自体は解析的に成立する。

既存のCPU入力clampは22を変更せず、EからLへの変換後の格納範囲を保証しない。
Lを65504へclampすると、円盤の積分照度は22でなく約4.444972717となり、約80%を失う。
太陽のEを減らす、円盤半径を広げる、画素をclampする方法でこの問題を隠さない。
AAは解像された円盤内部では重み1となるため、出力範囲の対策にはならない。

必要な設計候補は、最初のFP16格納より前に放射輝度全体へ共通倍率sを掛ける方法、
または必要な中間処理をFP32で保持する方法である。格納後の露出調整では失われた値を回復できない。
共通倍率では、散乱・地表反射・太陽直達を含む同じHDRターゲットの全入力について、
`s * max_component(L_total) <= 65504`を満たす必要がある。
上表の上限は円盤単独の条件であり、散乱や他の寄与の加算には追加の余裕が必要となる。
透過率は無次元のまま保つ。倍率をフレーム間で変える場合は、履歴を現在の尺度へ変換し、
露出計測・後段処理も同じ尺度で解釈する。太陽だけに倍率を掛ける変更ではない。
採用する尺度・形式・受渡し方法は未決定であり、今回は実装しない。

## 将来の円盤修正に残す未解決項目

将来のphysical合成の契約候補は次である。

```text
L_out = S + T_ground L_ground + D(omega) V(omega) T_top(omega) L_sun
L_sun = E_sun / [pi q (2 - q)]
```

Sは視線透過を既に含む散乱、Dは円盤内判定、Vは太陽までの可視性である。
地表へ届く視線では太陽直達項を遮蔽しつつ、`T_ground L_ground`を保持する。
地表へ届かない視線の地表項は0とする。遮蔽した視線の直達項は0として扱い、
無効な上端光路の値へ可視性0を掛けることで代用しない。
Sへ透過率を再度掛けない。実装がSと地表項をまとめて返す場合も、地表反射を二重に加えない。

| 未解決項目 | 将来必要な判断・証拠 |
| --- | --- |
| 入力契約 | E/L、RGBの基底、尺度、露出適用位置、半径の許容範囲、無効入力の扱いを定義する |
| HDR格納 | 共通倍率またはFP32経路を決め、全加算後の範囲と各中間格納をGPUで確認する |
| 合成と遮蔽 | 散乱を保持した加算へ直し、視線ごとの地表遮蔽と大気透過を直達項へ反映する |
| 円盤外の光彩 | physicalの人工haloをどう除外するか決める。既存art skyの色・glow・混合式は維持する |
| 部分遮蔽とAA | 太陽中心の可視性だけで円盤全体を消さず、画素内でD・V・Tの積を平均する |
| 互換性 | `CSky::Render`のart経路、公開レイアウト、半径のq表現を維持し、physicalだけの変更を製品描画で検証する |

`fwidth`と`smoothstep`による縁の平滑化は近似であり、積分照度の保存保証ではない。
画素フィルターに従って`D V T`を平均し、円盤の総照度は別途`cos(theta) dOmega`で積分する。
等しい画素面積を等しい立体角とみなさず、解像度・視野角・画素内位置・地平線との重なりを変える。
幾何学的な地平線の判定そのものは境界担当の結果を用い、本書では算法を変更しない。
